## 1. 定義と、分類が厳密にできる理由

| | 機構 | 判定 |
|---|---|---|
| **再分類死** | 境界で µ̂ が跳び、**同じ w が新しい入力サポートに対して再判定されて落ちる** | 死を挟む記録ペアが境界ペア (B, B+1)、B ≡ 0 (mod T) |
| **輸送死** | タスク内で力に運ばれて滑落する | それ以外（µ̂ 固定ペア） |

p̂ は w と µ̂ の両方で決まる。µ̂ 固定ペアで下がったなら原因は **w が動いたこと以外にありえない**。境界ペアなら w が動かなくても死にうる。

**曖昧なケースは出ない**: flip は step ≡ 0 (mod T) の記録点とその次の間で起きる（10 seed すべて 99/99）。境界の ±100 が毎 step 記録なので**粗い区間（1000 step）は境界を跨がない**。よって全ペアが排他的に分類される。打ち切りが生じるのは死亡**時刻**の分解能だけで、**経路の分類には生じない**。

## 3. 汚染の正体

再分類死の降下窓は**末尾に境界の跳びが一発入って終わる**。PE = |ΣΔcos| / Σ|Δcos| は大きな増分が一本コヒーレントに入ると上がるので、metric が張り替えを「極めて効率的な輸送」として読んでいた。

| 群 | 輸送増分のみ（µ̂ 固定ペア） |
|---|---|
| 再分類死の窓（170 本） | **0.3068**（D2-reclass・参考・判定に使わない） |
| 輸送死の窓（596 本） | **0.3754**（D2・主判定） |

既出の 0.3959 は、全 766 窓の 22%（170/766）を占める再分類死群が押し上げていた。**主張が汚染に依存していなかった**ので撤回は不要。

> **旧「全増分」列は削除した**（訂正記録 (b)）。commit 済みコードは降下窓の増分を µ̂ 固定ペアだけに絞って出力するので、再分類死群についても張り替えを含む値は出ない。両群で違うのは死亡の起き方だけである。

## 5. 死は事件ではなく定着（→ Q11）

- 1M 時点で dead は 947/1000、その **97.3% が p̂ = 0** の深い死
- しかし**生の下方クロスは 91〜92% が後で再点灯**する（再分類死 0.9107 / 輸送死 0.9197）
- 終端の死に落ち着くまでのクロス回数は**中央値 11 回**

タスク内ではゲートが閉じた瞬間に self も rest も勾配が厳密ゼロになるので**真に凍結**する。ただし**罠はタスクごとに引き直される**（境界で µ̂ が跳ぶ）ので、吸収は「そのタスクについて」でしかない。恒久死は**全タスク変種の罠の共通部分**に入ることであり、[[命題リスト]] Q11 の枠組みに数値が付いた形になる。

## 6. スコープ・留保

- **condA・w100・T=1e4・batch=1・`ratchet_log_0819` のログ限定**。condB へ外挿しない
- 死亡時刻の分解能が群で非対称（再分類死は必ず 1 step、輸送死はバルクだと 1000 step）。**時間あたりのハザードや t50 を群間比較しない**。分類自体には影響しない
- 「初回死は再分類が多く、終端死は輸送が優勢」の**読み**は**未検証**。旧版はこれを S-D0 と事前登録 D0 の対比から述べていたが、現行コードでは両者が同一統計量になったため**根拠が無い**（訂正記録 (c)）。主張として使わない
- `summary.md` §7 の逸脱・留保は **4 件**:
  1. **D1 の対照の作り方** — 死亡後のユニットは勾配が恒等 0 で ‖w‖ が動かないため、素の対照には構造的な 0 が混ざり q95 を押し下げる（判定を通りにくくする向き）。左端 alive 限定の副次値を `D1-alive` に併記
  2. **D2 の母集団** — 降下窓は比較可能性のため `ratchet_log_0819` の `death_events`（下方クロス後 1 周期回復しない最初の 1 個）をそのまま使い、経路ラベルと µ̂ 固定ペアのフィルタを掛けた。spec §3 の「死亡イベント = 全ての下方クロス」の母集団（`events.csv`・D0・D1・D5 が使う）とは**別**。両者を混ぜていない
  3. **D3 の生存群の区間** — 死亡群は恒久死に対応する降下窓で測るが、生存群には降下窓が定義できないため全記録区間で測った。**rest の符号安定率の群差は「同じ長さでの比較」ではない**。self の 1.000 は区間長に依らない
  4. **D2 の帰無の乱数列** — 符号置換の手続きは P3 と同一（窓ごと 1000 回）だが、抽選列は本 spec の `default_rng(20260821)`。P3 の 0.2177 とは**手続きが同じで乱数列が違う**
- 機構（なぜ境界で跳ぶか＝台帳の縮退）は次論文（[[論文スコープ分離]]）。現論文へ渡すのは「境界で各ユニットの発火閾値が離散的にずれる」の一文と、上記の群別数値のみ
