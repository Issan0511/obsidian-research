## 1. なぜ気になったか（Kubo 側の勘定・間違っていれば (1) で潰れます）

タスク長が 10,000 step 固定なら、$\eta\cdot$step を揃えたとき**サイクル数は揃わない**:

|                 | `LRoff0` | `LRoff0_lr0p00125` |
| --------------- | -------- | ------------------ |
| lr              | 0.01     | 0.00125            |
| step            | 5M       | 40M                |
| $\eta\cdot$step | 50,000   | 50,000（揃えた）        |
| **タスク数**        | **500**  | **4,000**          |
| $\bar z$        | −3.598   | −4.888             |

つまり「8 倍のタスク数で 1.36 倍深い」。**これは (a) まだ定着しておらずタスク数とともに深くなり続けている、(b) lr が平衡そのものを動かしている、のどちらでも起こる。** 同じことが [[命題1-5_上端則結果_0905]] 5-d にもあるので、1 回限りの偶然ではないと思う。

Kubo 側のモデルでは、この違いは意味が大きい。1 サイクルの期待変位のうち **lr に依らない項**（跳びの 2 次の項と、蹴りが折れ目を横切ることで出る一次の項）と **lr に比例する項**（過渡の雑音由来・Issa の R はその対角）を分けているが、
- (a) なら**すべての 5M 腕の末尾値は途中経過**で、腕どうしの比較は「同じタスク数どうし」に限られる。
- (b) なら lr は 2 つの入口を持つ（drift そのものと、暗黙正則化 $\propto\eta$ が決める**平衡スケール**）。実測の $\lvert v\rvert$ 0.604 → 1.268・$\lVert w\rVert$ 4.03 → 4.42 は後者の向き。

なお、**Kubo 側の理屈では「lr が小さいほど雑音由来の沈下が弱くなるので浅くなる」が出る**ので、観測（深い）を雑音の項だけで説明することはできない。

## 2. 聞きたいこと（3 行・既存ログのみ）

1. **タスク長は 10,000 step 固定か**（5M = 500 タスク・40M = 4,000 タスクという勘定で合っているか）。違えば以下は無効。
2. **`LRoff0_lr0p00125` の $\bar z$ 中央値を、タスク 451–500 の窓で**（＝ `LRoff0` と同じタスク数の時点で）読んだ値。ALIVE 規則・seed 中央値は末尾窓と同じ扱いで。
3. **`act_offset_0906` の settle 3 窓の判定は、$\Delta$（$c$ 腕 − $c{=}0$ 腕）に掛けたか、腕ごとの絶対値に掛けたか。** $\Delta$ だけなら、両腕に共通のゆっくりした drift は差で消えるので「定着」は共通 drift を排除しない——という理解で合っているか。

## 3. 答えで何が変わるか

| (2) の値                   | 読み                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| **≈ −3.6**（`LRoff0` と同じ） | 深さはタスク数だけの関数。lr は 1 サイクルあたりの変位に効いていない（lr 非依存の項が主役であることの強い確認でもある）。**ただし 5M の末尾値は途中経過**になる |
| **`LRoff0` より深い**        | 同じタスク数でも小さい lr が深い。lr は平衡スケール（$v$・$\lVert w\rVert$）経由で設定点を動かしている                         |
| **`LRoff0` より浅い**        | Kubo 側の符号の読み（雑音は沈める向き）が間違っている                                                            |

**Kubo の事前予測（値を見る前）**: 1 番目（≈−3.6）に 55%、2 番目に 35%、3 番目に 10%。

余力があれば: `LRoff0_lr0p00125` の $\bar z$ を**タスク数の対数に対して**引いた図（500 → 4,000）。直線なら 1 番目、500 付近で頭打ちなら 2 番目。ただし (2) の 1 点だけでもだいぶ分かる。

## 5. 回答（Issa 側・2026-09-07・事後解析 `registered=0` / `analysis_grade=posthoc_not_preregistered`）

走はゼロ。既存の `act_offset_0906` の `logs_tail`（ギガファイル配布分・sha256 先頭 `e3f52069a9aa` をマニフェストと照合済み）を読み直しただけ。窓・ALIVE 規則・bootstrap は `src/act_offset_analyze_0906.py` の `_window_indices` / `_alive`（`layer1_denom` の窓平均 > 0.25）/ `numpy.random.default_rng(20260906)`・2000 回をそのまま踏襲。

**手続きの検算**: 既登録の 2 値を同じコードで再計算したところ `verdict.csv` と小数 4 桁まで一致した（`LRoff0_1216` 451–500 = −3.5983、`LRoff0_lr0p00125_1216` 3951–4000 = −4.8884）。以下の新しい値も同じ経路で出している。

### (1) タスク長は 10,000 step 固定か

**固定。Kubo の勘定どおり。** `configs/act_offset_0906.yaml` の `analysis.task_period: 10000`。したがって 5M = 500 タスク、40M = 4,000 タスク。判定窓は本編が `tail_window_tasks: [451, 500]`、ラダーB（追補1・低 lr・40M）が `[3951, 4000]`。

### (2) `LRoff0_lr0p00125` のタスク 451–500 の $\bar z$

| 腕                                       | 窓（タスク）    | $\bar z$ 中央値 | 95% CI           | 生存 unit   |
| --------------------------------------- | --------- | ------------ | ---------------- | --------- |
| `LRoff0_1216`（lr 0.01・5M）               | 451–500   | **−3.598**   | [−3.634, −3.566] | 1000/1000 |
| `LRoff0_lr0p00125_1216`（lr 0.00125・40M） | 451–500   | **−3.222**   | [−3.347, −3.096] | 996/1000  |

**CI は重ならない。**§3 の表では 3 番目「`LRoff0` より浅い」（Kubo 事前 10%）に落ちる。

### (3) settle 3 窓の判定は $\Delta$ か絶対値か

**$\Delta$（$c$ 腕 − $c{=}0$ 腕）に掛けている。Kubo の理解どおり。** `src/act_offset_analyze_0906.py` の 315–323 行が `za - zb` の中央値を 3 窓で取り、`unsettled` の判定はその $\Delta$ だけを見ている。`verdict.csv` には腕ごとの絶対値 `settle_zbar` と差の `settle_dzbar` が両方載っているが、判定に入るのは後者のみ。したがって**両腕に共通のゆっくりした drift は差で消えており、「定着」は共通 drift を排除しない**——という追伸の読みで合っている。

### (4) 余力ぶん — タスク数に対する $\bar z$

各行は「窓の終端タスク」で、窓幅は 50 タスク（例: 500 の行は 451–500）。

$\log(\text{タスク数})$ に対してほぼ直線で、**500 付近の頭打ちは見えない**。低 lr 腕はタスク 750（−3.602）で `LRoff0` の 500 タスク値を追い抜く。`LRoff0` 自身もタスク 400 → 500 で −3.539 → −3.598 とまだ動いており、5M の末尾値は途中経過。

### (5) 差し戻したい点 — §1 の本文と §3 の表が食い違って見える

§1 の本文には「**Kubo 側の理屈では『lr が小さいほど雑音由来の沈下が弱くなるので浅くなる』が出る**」とある。それなら「同じタスク数で浅い」という観測は、雑音の符号の読みが**当たっている**ことになる。ところが §3 の表の 3 行目は「`LRoff0` より浅い → Kubo 側の符号の読みが間違っている」と逆向きに書いてある。

どちらが意図した対応づけか判断できないので、**判定の記録はここで止めている**。表のラベルが逆でよいか、それとも §1 の本文の方を読み替えるべきかを教えてください。

なお観測は 3 番目の枝だけを満たすのではなく、1 番目の但し書き「ただし 5M の末尾値は途中経過になる」も同時に満たしている（(4) のとおり両腕とも止まっていない）。一方で 1 番目の本体「深さはタスク数だけの関数」は**外れ**で、同じタスク数なら低 lr の方が浅い。
