## 2. ★ Linear ベースラインの構成が違う（B の答え）

`cfg/flip_one/linear.json`:

```json
"agent": "linear",  "num_features": 0,  "hidden_activation": "",
"step_size": [0.03, 0.01, 0.003, 0.001, 0.0003]
```

`lop/nets/linear.py`:

```python
class MyLinear(nn.Module):
    def __init__(self, input_size, num_outputs=1):
        self.fc1 = nn.Linear(input_size, num_outputs)
```

> **原典の Linear ベースラインは隠れ層ゼロの単層線形回帰である。**

当方の `LIN5` は leaky($a$=1.0) の**隠れ 5 ユニット付き**。関数クラスは同じ（$x$ のアフィン関数）だが、**パラメータ化が違う**（$x \mapsto v^\top(Wx+b)+c$ のボトルネック経由）ため最適化の力学は別物であり、初期化のスケールも異なる。**同じベースラインではない。**

**step size も違う。** 原典の linear は 5 点（0.03 を含む）、活性化側は 3 点。プロットコードは linear を `setting_idx=0` で取るので **リストの先頭 = 0.03**。当方は全腕 0.01 固定。

## 4. ★ 原典本文は「leaky は Linear より上」と言っていない（A の答え）

### 4-1. 本文の記述

Appendix B の該当箇所は、**ReLU と tanh** では可塑性喪失が深刻で誤差が線形ベースラインの**水準まで上がる**とし、**ELU** のような他の活性化では可塑性喪失は**それほど深刻ではない**が有意には存在する、と述べている。

- **leaky-ReLU は本文で一度も言及されていない。**
- ReLU について書かれているのは「水準に**達する**」であって「**上回る**」ではない。

したがって [[容量不足レジームの機構_0830]] §5.2 が記録した目視読み「**leaky は Linear より上（重症）、ELU のみ Linear の下**」のうち、**leaky に関する部分は原典本文に対応物を持たない。**

### 4-2. 目視読みには内部矛盾がある

vault の記録は Linear を **leaky パネルで 0.79、ELU パネルで 0.85** と読んでいる。**Linear は両パネルで同一の走のデータ**なので、同じ $x$ で読めば同じ値でなければならない。

§3-3 のとおり **パネルごとに y 軸目盛が違う**ので、目盛の異なるパネル間の目視比較には系統誤差が入る。**0.06 のずれは、測ろうとしていた効果 0.08 dex と同じオーダーである。**

→ **目視読みを「原典の主張」として引かない。**
