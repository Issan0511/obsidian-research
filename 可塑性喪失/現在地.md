## 8/29 の LoP 防止アーキテクチャのプログラム

正本: **[[LoP防止アーキテクチャ_0829]]**（設計・先行監査・作業表）。秘書 task_119 / 121 / 123。出典チャット `arch_lop_0829`。

| 走 | 結果 | ノート |
|---|---|---|
| `mlp2_phase0_0829`（2 層 × 100・1M） | `LOP_ABSENT`。ただし判定の脚は 1 本で補間 regime。**1M では足りなかった** | [[多層Phase0結果_0829]] |
| `mlp2_phase0b_0829`（3 腕・5M） | **3 腕とも `LOP_PRESENT`**。容量は死を防がず遅らせるだけ（幅 600 で生存 3/600）。腕効果は `H0_REJECTED` だが**幅の係数は床検閲の産物の疑い** | [[多層Phase0b結果_0829]] |
| `mlp2_phase1_0829`（候補 A・5 腕・5M） | **両層中心化 = `A_EFFECTIVE`**、入力層のみ = `INCONCLUSIVE_SPLIT`、第2層のみ = **数値発散で未検証**。深さ1 の centering は 5M でも持つ | [[多層Phase1結果_0829]] |

**最大の機構的発見**: 第1層を中心化すると**第2層自身の壁が立ち上がる**（wall_trend 0.044 / p=0.754 → 0.405 / p=0.002、第2層 strict_dead 87.9% → 90.7%）。隠れていた理由は µ の枯渇ではない（µ/Σ 比は 0.547 対 0.500 でほぼ同じ）。分けたのは**入力の支持の豊かさ**（第1層 alive 21 → 65）。→ 柱1 の多層一般化として本文化済み。

**ReLU の整流定数**: 零平均ガウス事前活性で $\|\boldsymbol\mu\|/\sqrt{\operatorname{tr}\Sigma}=0.684$。実測 0.707–0.740。**tanh では 0 なのでこの経路は ReLU 特有。**

**先行監査**: Chiley et al. 2019 の Online Normalization を原典確認し、Dohare 側の ON 腕に weight decay が無かったことを確認（[[LoP防止アーキテクチャ_0829]] §5）。「ON の失敗は実効学習率の崩壊で説明できる」は**仮説**（ON + L2 の腕が存在しない）。

## 開いている穴

1. **柱3 の遷移帯は時間依存かもしれない**（8/29 新設・最優先）。柱3 は 1M step の測定で、下側の `‖µ‖=2.333` 腕は 1M 時点で既に strict_dead 0.556 だった。5M へ延ばすと跳びが消える可能性がある。**結果次第で柱3 の「閾値型」と v4 の一行が変わる。** spec 起票済・未実行 → [[柱3遷移帯の時間依存_spec_0829]]
2. **`L2_A2`（第2層のみ中心化）が数値発散で未検証**。「第2層単独では効かない」は言えない。境界直後（step 141000 = 境界 +1000）の共通モード衝撃という仮説あり・未検証
3. **eff_rank は「死」と「平均支配」を区別しない**（両層中心化の第1層は alive 98.3 で eff_rank 3.14）。[[論点マップ]] §9 の「eff_rank が最も信頼できる指標」に跳ね返る。平均除去した活性での再定義が要る
4. **Phase 1 の署名表が「介入が早期を悪化させる」型を覆っていない**。全腕 `NO_LOP_PREVENTION_SIGNATURE` は表の欠陥の産物で、補助統計（傾き）は防止方向。**「LoP を防いだ」とは書けない**状態が続く
5. **Q17 が整流フレームを反証**（8/28 から継続）。「ほぼ対称な rest 撹拌」は撤回済み。系統的な rest 駆動をどう帳簿化するかが未決
6. **柱3 の枠づけ**（8/27 部分裁定・先生の最終裁定待ち）
7. 作業3(a) の Issa 確認と [[命題リスト]] への転記、v3 転記
