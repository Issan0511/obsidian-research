## 1. 直前に何が決まったか（前提）

2026-09-10 に登録走 `clamp_horizon_0910`（[[長い地平線で沈下と幅を分ける_結果_0910]]）で:

**ただしこれは leaky・ELU の話で、ReLU・GELU・SiLU は別。** 下の穴が残っている。

## 3. 穴と、塞ぐ走（この順）

### R1 — ReLU の t400 + クランプ（箱 B）★最優先・最安

**問い**: 「沈下 → 死 → LoP」は、幅の結果と同じ箱で立つか。
**走**: `clamp_horizon_0910` の `ARMS` に `('R','none')` を足すだけ。t21–400・{ref, dclamp, wclamp, wcap2} × seed 0–2。**活性化は実装済み**（`H.ARMS['R']`）。3 ジョブ × 約 17 分、2 並列で **約 34 分**。
**G1 の当てどころ**: `results/leak_ladder_force_posthoc_0910/R_s{0,1,2}_units.npz` に **`ref_cnorm_i_t1`〜`t100` が per-unit で入っている**（100 キー・確認済み）。`clamp_horizon_0910.g1_check` は `results/width_sink_clamp_0909/` を見に行くので、**R のときだけ参照先を切り替える必要がある**（R は width_sink_clamp に無い）。ref 腕のみ t1–100 で照合。dclamp/wclamp の committed 参照は R には存在しないので、G1 は ref 腕だけになる。**その旨を spec に書くこと**（G1 の被覆が LR/ELU1 より弱い）。
**予測（Claude・登録済みでない・登録し直すこと）**: ReLU の死は t400 まで伸び続けるが、精度損失の大半は幅経由で `dclamp` は効かない（ρ ≤ 0.2）。**外れれば V9 の「ReLU は別経路」が箱 B で初めて立つ。**

### G1 — GELU・SiLU を箱 B へ（実装済み → 走らせる）

**実装は完了している**: `src/valley_acts_0910.py`（repo `collective_kick_0908` の `6b28ecf`）。`GELU`（厳密 erf 形）と `SiLU`（β=1）を `H.Activation` と duck-type 互換で実装し、**落ちうる自己検査**を付けた:

| 検査 | 値 |
|---|---|
| phi が torch のカーネルと一致 | 8.9e−16 |
| dphi が autograd と一致 | 2.2e−16 |
| 谷底 $z_c$ が dphi の根 | GELU −0.7517915239（残差 3.4e−10）／SiLU −1.2784645428（8.5e−12） |
| **符号構造** dphi>0 ($z>z_c$)・dphi<0 ($z<z_c$) | 両方 True |
| phi の最小が $z_c$ | 一致（1e−3 格子） |
| 変異対照（$z_c+0.05$ で根の検査が発火） | > 1e−3 |

`python -m src.valley_acts_0910` で再実行できる。

**走の順**:
1. **`long_horizon_0910` に GELU/SILU を足す**（参照軌道 t1–400・3 seed）。これが無いと次の G1 が当てられない。6 ジョブ × 約 3 分＝**約 9 分**。`long_horizon_0910` は `elu_growth_0909` を G1 に使うので、**新活性化には committed 参照が無い** → G1 の代わりに (a) 測定の非侵襲（測定ありと測定なしで最終状態が bit 一致）と (b) 上の自己検査を検算にする。**「G1 0.0」と書かないこと**（比較対象が無い）。
2. **`clamp_horizon_0910` に GELU/SILU を足す**（t21–400・4 クランプ）。G1 は 1 で作った参照の t1–100。6 ジョブ × 約 17 分＝**約 51 分**。

**予測（Claude・要登録）**: (a) 死亡が ELU のように 1 割で頭打ちにならず伸び続ける、(b) **`dclamp` が損失を戻す**（ELU では戻さなかった）、(c) `wclamp` も戻す。**(b) が決め手** —— 立てば「谷越え型では沈下が LoP を作る」が介入で立ち、V9 の二分（ゲートが正のまま残る型／消える型／反転する型）が確定する。

**なぜそう予測するか**（V9 §2 段階 2 の導出）: 行平均への押しは $\partial L/\partial m_i=\sum_x\varphi'(z_i)e_i(x)S(x)$。負側標本の「もっと活性化しろ」（$e<0$）は、leaky（$\varphi'=+a$）・ELU（$+e^z$）では**浮き**になるが、谷の向こう（$\varphi'<0$）では**沈み**になる。深くするほど活性化が 0 に近づく＝「増える」から。復元の regime が無いので死が飽和しない。

### R2/G2 — `why_down` を 4 活性化で（駆動源の測定）

**問い**: 上の符号反転は**導出であって測定でない**。測る。
**走**: `src/why_down_posthoc_0910.py` を R・ELU1・GELU・SILU で回す（いま LR・SNA のみ）。1 腕 約 4 分、4 腕で **約 8 分**（2 並列）。
**見るもの**: 負側の $e\cdot\varphi'$ の符号。leaky/ELU は負（浮き）、GELU/SiLU の谷以深は正（沈み）になっているはず。ReLU は負側の $\varphi'=0$ なので寄与ゼロ＝浮きが存在しないことの確認。

## 5. 前セッションのレビューで潰した罠（同じ轍を踏まないこと）

`clamp_horizon_0910` は投入 13 分後に敵対的レビュー（4 レンズ→検証・31 エージェント）で **21 件中 15 件 CONFIRMED・blocker 2 件**が出て、走を止めて直してから回し直した。教訓:

1. **反空虚の下限を「走全体の running max」で床上げすると、地平線を伸ばしたとき対照が落ちる。** 対照は t21 で測る定数なのに下限だけが ‖W‖ とともに育つ。検証エージェントが t400 まで再走して LR seed2 が floor 5.44e−6 > 対照 5.11e−6 で落ちることを実測した。**対照の下限は対照が走る状態（t20）の床で評価する。**
2. **乖離ラベルの第 2 項を「介入が触らない量」で書かない。** ‖W̃‖ の水準比は dclamp では常に ~1 で落ちようがなかった。較正に使った量（σ の傾き比）で書く。
3. **ρ ≤ 閾値 を「無効果」にすると ρ<0（＝止めたら悪化＝保護的だった）を飲み込む。** 害の帯を先に切り、どちらの予測も支持しないと明記する。
4. **`REMOVES` は「水準のずれ」と「蓄積が止まった」を分けない。** 傾きの条件を足す。
5. **`_assert` が ck に無いキーを飛ばすと、実行されなかった検査が「合格」に見える。** 全キーの存在を要求する。G1 の per-unit 側も件数ガードが無いとキー 0 一致で 0.0 通過。
6. 空虚な検査は**通算 7 回目**。変異対照を必ず書き、それが桁で発火することを確かめる。
