**GCP に逃がすのは不可（2026-09-05・実測で確定）**。理由 3 つ、どれ 1 つでも致命:
1. **臨界パスは 15M 腕 1 本の単スレッド 52 分**でコアを増やしても縮まない。プロジェクトの `CPUS_ALL_REGIONS = 32` は全リージョン合計の上限で、SMT を考えると**実コア 16 < ローカルの 20**（i7-14700K・8P+12E）。per-core クロックも約半分 → GCP は 2〜3 倍**遅い**。
2. **別 CPU では float32 のバイトが変わる（実測）**。`ATEN_CPU_CAPABILITY` で経路を切り替えると einsum/elu/tanh/softplus の**4 つ全部**でハッシュが変わる。さらに `MKL_VERBOSE` で毎ステップの einsum が **MKL SGEMM_BATCH・`CNR:OFF`・Intel AVX2+DL Boost カーネル**を選んでいることを確認。このマシンは **AVX2 止まりの consumer 部品**で、GCP の Intel 系は全部 AVX-512、AMD 系は MKL のベンダ判定が別経路 → **「Intel・AVX2 最大・VNNI あり」は GCP に存在しない**。`S-null`/`S-null-E`/`S-mirror` が同時に落ち、**S-mirror は命題 1 の確証的統計量**。しかも走中の検査なので **620 CPU 分を使い切った後に判明**する。
3. Spot 不可（`PREEMPTIBLE_CPUS = 0`）・機種は quota で 3 つに縮む・生ログは見積りの 2 倍（~7 GB）・腕の途中チェックポイントが無いので中断＝その腕が丸損・解析は committed 参照 1.6 GB が要るのでどのみちローカル。
→ **一般則: bit 一致検査を持つ走は、参照ログを作ったマシンから動かせない。** 別マシンに出すなら参照腕も同じマシンで作り直す設計にしてから。
