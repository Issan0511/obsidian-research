## 1. ファイルの置き方

- **1 論点 = 1 ファイル。** 冒頭に `親 / 状態 / 更新` を書く
- **フォルダを勝手に作らない。** 下のフォルダ表に無いフォルダが要ると思ったら、作る前に Issa に聞く（2026-09-29・Issa）。`理論/` は 9/7 に Claude、`実験/` は 9/20 に Codex が断りなく作り、放置されているうちに他のセッションが使い始めて置き場が二重になった。置き場所に迷ったら表の中でいちばん近いフォルダに置く
- 状態は **未着手 / 検証中 / 決着 / 凍結** の 4 値
- **論点が増えたら [[論点マップ]] 冒頭の全節索引に 1 行足し、親からもリンクを張る**（9/3 改訂。従来は [[研究索引]] の論点ツリーだったが、同日ハブから引退させた。**既存の節番号は動かさない** — 全ノートから §番号で参照されているため、追加は末尾へ）
- **破棄した主張は消さずに取り消し線で残す。** 理由も併記する
- **フレーム交代で死んだ論点は `過去の遺物/` へ移す**（削除しない）。移動時に **Next action は廃止と明記する**。未実施であることは残す理由にならない
- 決着した論点は Slack Canvas に昇格させる（Obsidian = 自分用の全論点、Canvas = 共同研究者に見せる決着済み）
- **新しい記号・略号を導入したら [[用語と記号]] に 1 行足す**

## 2. 数値の扱い

- **数値は `results/*/verdict.csv` と `summary.md` からのみ転記する。チャットの言い回しを出所にしない**
- **事後追加の数値は「事後」ラベルと必ずセットで運ぶ**
- **実験は spec を実行前にコミットして事前登録する**（`rank_int_0814` 以降）。判定基準を先に凍結し、想定外の分岐に落ちたらそれ自体を記録する。**追補も同様**
- **事前登録の統計量が痩せたら、事前登録版を残したまま補遺を「事後」ラベルで足す**
- **計画文書（事前登録済み）は結果を見た後に書き換えない。** 判定・改訂は該当論点ファイルと [[論点マップ]] に記録する（実行済みを示す帰趨バナーを末尾に足すのは可）
- **結果 commit は push を確認して初めて「commit 済み出力」とみなす**（8/26 の push 監査で 18 本中 1 本の MISS を検出。**8/27 裁定済み・先生同意**。引用している commit がリモートに存在するかの照合を、先生への共有前の手順に入れる）
- 再現しなかった旧値は消さず、**「再現せず・撤回」として格を落として残す**
- 真の事前登録が不可能な再現走では `repro` / `prereg` / `report` の三層で格を分け、**引用時に tier を落とさない**

## 3. 実験の選び方

## 5. 計測の教訓（①〜⑩）

出所は [[論点マップ]] §9。ここには見出しだけ置く。

1. 事前登録の判定基準が仮説の一方に依存していると、その一方が崩れたとき基準ごと無意味になる
2. **指標が測定対象の一部で恒真になっていないか事前に確認する**
3. ラグの異なる統計量を比較しない
4. チャットの言い回しを数値の出所にしない
5. 絶対値の損失をレベル間で比較しない
6. 複雑度ダイヤルは `f` ではなく教師幅
7. 指標が依存している基準量（µ̂）が動く点を跨いでいないか確認する
8. 事前登録の統計量が痩せたら、事前登録版を残したまま補遺を「事後」ラベルで足す
9. 「再学習不要だから安い」を採否基準にしない
10. **②の恒真チェックは判定指標だけでなくサニティ側にも掛ける**（4 例目が `r_swap_0824` の S4・S5）
11. **二値化した endpoint は飽和しうる。** 事前に「全腕が同じ値に張り付く可能性」を検討する（`mlp2_phase0b_0829` の `n_onset` が 3 腕とも 9–10 で天井に張り付き、判別情報は水準側にあった → [[多層Phase0b結果_0829]] §6-1）
12. **regime ラベルの閾値は、比較したい両側が別ラベルになることを確認してから凍結する。** 参照値がどの窓の量かを合わせる（G-pre が定常状態の unfit ≈ 0.14 を根拠に初期窓へ閾値を置き、canonical な腕まで「適用外」に分類した → 同 §6-2）
    - **2 例目（8/30）**: 第2層入力の µ/Σ 比 0.740 / 0.707 は **`final_t500`（task 500 単点）** の量だが、[[多層Phase1結果_0829]] §4-1c 以降の各草案が**窓を書かずに**引いていた。同じ量は late 窓（451–500）で 0.848 / 0.718、task 1 で 1.394 / 0.734 で、**無介入腕は窓で 2 倍近く動く**。窓を落としたまま「閉形式 0.683 と整合」と書くと、**実際には末尾窓を選んだときにだけ成り立つ一致**を無条件の一致として運んでしまう。同じ §4-1c 内で dose を「early → late」、比を「task 500」と**別の窓で並べていた**のも同じ事故。**数値を書くたびに窓のラベルを添える。異なる窓の量を同じ文に並べない。**
    - **付随して（8/30）**: 転記元は `results/*/verdict.csv` と `summary.md` に限る（§2）が、この 2 数値は `layer2_input_stats_0830/window_levels.csv` にしかない（同 run の `summary.md` は late 窓しか載せていない）。**§2 の 2 ファイル以外から引くときは、ファイル名と行の識別子（窓・metric）まで書く。**
13. **studentized bootstrap は分散が潰れる regime で発散する。** 退化検出と fallback を spec に最初から書く（`mlp2_phase0_0829` で CI 上端 91.9・±10¹³、`mlp2_phase0b_0829` で退化ガードが設計どおり作動）
14. **マスクの要素数と、それが表す物理イベントの回数が一致するかを検算する。**（`centered_death_posthoc_0831`・8/31）境界窓を `step % 10000 == 1000` で定義すると 500 個拾うが、`flip_state` の変化は 499 回しかない。余分な 1 個は step 0 → 1000 の **EMA 初期収束過渡**で、タスク切替ではない。実装の S3 は不一致を note に記録していたが**マスクは直さなかった**。E3・E4 の判定は不変だったが（−4.297 → −4.199）、**比を取る endpoint では非対称に効く** → [[オラクル中心化_spec_0831_追補1]]。教訓②の変種で、恒真性ではなく**対応の個数**を検算する
15. **running statistics を持つ介入では step 0 は別レジームであり、総和 endpoint に初期過渡を含めない。**（同上）`centered_death_posthoc_0831` の E2 は step 0 起点の総和だったため、EMA 収束前の大きな $M$ を拾って登録判定が `MU_CHANNEL_ALIVE` になった。step 10,000 起点の感度分析は `BIAS_CHANNEL_DOMINANT`。**登録判定は差し替えないが、起点の選択を endpoint 定義に明記する**のが正しかった
16. **解析的な閾値の適用範囲を、endpoint と同じ厳しさでサニティにも書く。**（同上）S1 の十分条件 $\beta\le-\sqrt5 \Rightarrow \hat p=0$ は $\kappa=\lVert w_{\rm free}\rVert_1/\lVert w_{\rm free}\rVert_2\in[1,\sqrt5]$ から出ており、**この $\sqrt5$ は condA の rnd 5 bit という layer 1 の入力構造の定数**。layer 2 の支持は別物なので適用できず S1 が FAIL した。E1–E4 が使う layer 1 は全件 PASS で実害はなかったが、**定数がどの層のどの構造から来ているかを書く**。教訓⑩（サニティ側にも掛ける）の適用範囲版
17. **吸収する系では総和 endpoint が生存時間で打ち切られる。腕間で比べる前に率へ直す。**（`center_oracle_0831`・8/31）P1 は 5M 全体の $\Delta\beta^{\rm bnd}$ の腕間比だったが、`L1w100_Aexact` は中央値 **36 境界**で全ユニットが凍結し（`L1w100_A1` は 387 境界）、残りは $\Delta\beta=0$ を積む。$R_{499}=0.5167$ は**生存境界数の比**であり、生存中 1 境界あたりに直すと符号関係が反転した（−0.0509 対 −0.0211、生存本数を揃えても −0.0489 対 −0.0279）。教訓⑪（二値 endpoint の飽和）の連続版で、**飽和ではなく打ち切り**。吸収・凍結・停止のある系では、spec の段階で「総和と率の両方を出す」と書く → [[オラクル中心化_spec_0831_追補2]]
