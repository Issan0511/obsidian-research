## 1. ファイルの置き方

- **1 論点 = 1 ファイル。** 冒頭に `親 / 状態 / 更新` を書く
- 状態は **未着手 / 検証中 / 決着 / 凍結** の 4 値
- 論点が増えたら [[研究索引]] の論点ツリーに追記し、親からもリンクを張る
- **破棄した主張は消さずに取り消し線で残す。** 理由も併記する
- **フレーム交代で死んだ論点は `過去の遺物/` へ移す**（削除しない）。移動時に **Next action は廃止と明記する**。未実施であることは残す理由にならない
- 決着した論点は Slack Canvas に昇格させる（Obsidian = 自分用の全論点、Canvas = 共同研究者に見せる決着済み）
- **新しい記号・略号を導入したら [[用語と記号]] に 1 行足す**

**spec は実行が済んだら `spec/実行済み/` へ移す。実行前監査で失効したら `spec/失効/` へ移す。** `spec/` 直下に残っているものが「次に確認・実行できる有効な spec」になる。実行済み spec は結果の**事前登録の証拠**、失効 spec は設計変更の履歴なので、どちらも捨てず `過去の遺物/`（フレーム交代で死んだ論点）とは分ける。実行済みへの移動時は**冒頭の状態行を実行済みへ更新する**（本文は起草時のまま。§2 の「計画文書は書き換えない」の唯一の例外が状態行 1 行）。失効時は本文を変えず、末尾の帰趨バナーから後継を指す。

**移動は `obsidian_move`（`git mv`）または Obsidian 上のドラッグで行う。** MCP には `move` が無く、read → create → delete で代替すると全文を打ち直すことになり、(a) 数値の転記事故、(b) 内容が変わることによる git のリネーム検出漏れ＝`obsidian_git_blame` の追跡切れ、の 2 つを招く。

## 2. 数値の扱い

- **数値は `results/*/verdict.csv` と `summary.md` からのみ転記する。チャットの言い回しを出所にしない**
- **事後追加の数値は「事後」ラベルと必ずセットで運ぶ**
- **実験は spec を実行前にコミットして事前登録する**（`rank_int_0814` 以降）。判定基準を先に凍結し、想定外の分岐に落ちたらそれ自体を記録する。**追補も同様**
- **事前登録の統計量が痩せたら、事前登録版を残したまま補遺を「事後」ラベルで足す**
- **計画文書（事前登録済み）は結果を見た後に書き換えない。** 判定・改訂は該当論点ファイルと [[論点マップ]] に記録する（実行済みを示す帰趨バナーを末尾に足すのは可）
- **結果 commit は push を確認して初めて「commit 済み出力」とみなす**（8/26 の push 監査で 18 本中 1 本の MISS を検出。**8/27 裁定済み・先生同意**。引用している commit がリモートに存在するかの照合を、先生への共有前の手順に入れる）
- 再現しなかった旧値は消さず、**「再現せず・撤回」として格を落として残す**
- 真の事前登録が不可能な再現走では `repro` / `prereg` / `report` の三層で格を分け、**引用時に tier を落とさない**

## 3. 実験の選び方

- 実験の候補は [[命題リスト]] の「閉じる作業」列に置き、**実際に回すと決めたものだけタスク化する**。未実施の実験を秘書システムに起票しない
- **v3 のどの柱も閉じないものは回さない**
- **「再学習不要だから安い」を採否基準にしない。** 実施の正当性は「**反論欄に既に書いてある穴を閉じるか**」で判断する
- 実施済みの走の結果から**追跡実験を自動起案しない**
- ~~機構の深掘りは 8/21 合意の枠外。**先生の承認を取ってから回す**（防衛タスクは除く）~~ → **2026-08-29 Issa 判断で取り下げ。** 理由: v4 で主軸を µ/Σ に移し、実用モデルへの接続（µ 考察 §3・§5）が主張の責任範囲に入ったため、機構の深掘りを事前承認制にする段階を過ぎた。**事前登録（§2）と spec のコミットは従来どおり必須**で、緩めたのは「回す前に先生の承認を取る」という手続きだけ

## 4. 委譲と引き継ぎ

- **大規模な実装・実行は外部エージェント（Codex 等）に委譲してよい。** 事前登録は委譲元が先に固定し、HANDOFF で背景を全部渡す。**実行結果は独立に検証してから取り込む**
- **新しいチャットは [[現在地]] → [[引用禁止]] → [[運用ルール]] の 3 ファイルで立ち上がる。** 個別論点に入るときだけ [[研究索引]] の論点ツリーから辿る
- MCP からの commit は `author` と `message` を渡し、subject を `[author]:message` に統一する。**`author` にはチャット名を入れる**
- 行の最終変更者は `obsidian_git_blame` で確認する

## 5. 計測の教訓（①〜⑩）

出所は [[論点マップ]] §9。ここには見出しだけ置く。

1. 事前登録の判定基準が仮説の一方に依存していると、その一方が崩れたとき基準ごと無意味になる
2. **指標が測定対象の一部で恒真になっていないか事前に確認する**
3. ラグの異なる統計量を比較しない
4. チャットの言い回しを数値の出所にしない
5. 絶対値の損失をレベル間で比較しない
6. 複雑度ダイヤルは `f` ではなく教師幅
7. 指標が依存している基準量（µ̂）が動く点を跨いでいないか確認する
8. 事前登録の統計量が痩せたら、事前登録版を残したまま補遺を「事後」ラベルで足す
9. 「再学習不要だから安い」を採否基準にしない
10. **②の恒真チェックは判定指標だけでなくサニティ側にも掛ける**（4 例目が `r_swap_0824` の S4・S5）
