## 0. 一行

**実ラベルの公開データで、初めて Snake 族（SNA・KKA・KKT1）が首位に立った。** 原典の λ の L2 Init には 20 seed で 19/20 勝ち、箱ごとに λ を調整した L2 Init とは事前登録の同等性判定で ±0.5 pt。relu_doors の扉 H はこの箱でも沈下を完全に止めるが階数を戻さず、処方としては KKT1・L2 Init に 0/10 で負ける。16 腕の順位は原典の 780 更新に固有で、予算を 10 倍にすると扉の利得の符号が反転する。

## 1. 箱

Kumar, Marklund & Van Roy (2024) の第 4 問題「5+1 CIFAR」を MLP に移植。

| 項目 | 固定内容 |
|---|---|
| データ | CIFAR-100。hard タスク = 5 クラス × 500 枚 = 2500 枚、easy タスク = 1 クラス 500 枚。偶数番が hard・奇数番が easy で交代、30 タスク（hard 15・easy 15）。クラスは再訪しない（1 seed で 90 クラス） |
| 予算 | 780 更新/タスク × batch 32（hard で 10 epoch、easy で 50 epoch）。原典 Table 1 の値 |
| 網 | **3072-100-100-100 の MLP**（原典は CNN。ここだけ変えた） |
| 最適化 | Adam lr 1e−4・WD なし・正規化層なし。原典の Table 4 が 5+1 CIFAR・Adam・Baseline に与える値 |
| 入力 | `std`（CIFAR-100 の定数で標準化）。`raw` は扉の対照でだけ使う |
| 指標 | hard タスクの **更新前** online 精度（原典の "average online task accuracy"）。後期窓 = hard 21–29、早期窓 = hard 1–9 |
| fresh 対照 | 最後の hard タスク（t29）の同じバッチ列を初期化した網で 780 更新だけ学習し、`fresh gap = fresh − continual`。正でなければ「劣化」でなく「難しくなっただけ」 |
| seed | 0–9（追試は 10–19、先行走は 100–102） |
| 費用 | **1 走 20 秒**（0.69 ms/step・R=10 束ね）。16 腕 × 10 seed で 7 分 |

**先行走（`R` 単独・3 seed・4 セル）で「ReLU が落ちるか」を先に確かめてから本走に進んだ。** 4 セルすべてで単調劣化と fresh gap > 0 が成立し、既定セル `std` × lr 1e−4 で本走。条件を探し回っていない。既定セルの ReLU は後期窓 .498 で崩壊（< .20）はしない。死ぬのは第 2 層だけ（3072 次元を読む第 1 層は 30 タスクで死者ゼロ）、ゲートは 250 倍閉じ（mob l2 .740 → .003）、殺しているのは easy タスク（1 クラスを 50 epoch 当てて出力を定数に押し込む区間）。

## 4. 追補 4: relu_doors の扉をこの箱へ

扉の定義は親箱と同じ（C = 平均画像を引く・H = relu(z) − EMA 平均 β=.01 の定数・B = b2 に decoupled WD）。箱に依存する 2 つは導出し直した: C の平均画像は **CIFAR-100 訓練集合 50,000 枚の定数**（タスク境界や未来を漏らさない）、λ は probe から **0.835**（親の 0.1713 を借りたら 5 倍弱かった）。**`std` は標準化だけで r = 0.129 と親箱の C の到達点（0.121）にすでに居る**ので、C の効果は `raw` でしか測れない。11 走・4 分。

- **水準の代償**: CH は t1 の時点で R より 7 pt 低い（online .606 対 .675）。「低いところで落ちない」のが扉 H、「高いところで落ちない」のが KKT1。
- 予測: Issa「CH = CHB で、KKT1・l2init ともほぼ変わらない」は D1 当たり・D2・D3 外れ（この箱で初めて外した）。Claude 3/6（D4b「raw でも H 単独が勝つ」を 35% と低く見た）。

| 設計 | 腕 | 後期窓 | train 末 | fresh gap | mob l2 | eff_rank l2 |
|---|---|---|---|---|---|---|
| 780（登録セル） | R / CH / KKT1 | .424 / .560 / .667 | .645 / .619 / .785 | +.228 / +.018 / +.035 | .002 / .605 / .830 | 9.1 / 12.7 / 50.9 |
| (a) 7800/7800 | R / CH / KKT1 | **.874** / .785 / **.938** | .998 / .984 / 1.000 | +.094 / +.066 / +.019 | .042 / .358 / .866 | 37.0 / 17.8 / 67.9 |

- 登録ラベル: CH − KKT1 は (a) −.156・(b) −.152 で **`LEVEL`**（差は縮まず広がった）。(a) と (b) が一致したので easy の応力 ×10 の交絡は結論を動かしていない。
- **ただし train 末の差は −.150 → −.016 / −.010 まで縮んだ**。CH は「届かない」のではなく「遅い」。登録した 3 ラベルは「到達点は追いつくが online は追いつかない」を書き分けられていなかった（判定の設計ミスとして記録）。正しい言い方: **CH の不足は適応の速度にあり、それは低階数の表現で決まるので予算では買えない**（eff_rank は 10 倍でも 17.8 / 8.0）。
- **扉の利得は予算に依存する**: `CH − R` は 780 で +.116（10/10）、7800 で **−.086（0/10）**。7800 では R 自身がほぼ回復し（死 .095・eff_rank 37）、扉の水準の代償だけが残る。`KKT1 − R` は両予算で勝つ（+.226 / +.063・10/10）。**16 腕の順位は原典の 780 更新に固有**で、「この活性化は可塑性喪失を防ぐ」を予算に依らない主張として書かない。なお 7800 でも R の fresh gap は +.094（10/10）で、消えたのは崩壊であって喪失ではない。

## 6. §18 精度の三つ組（事後・登録外）

「精度」は 3 つが混ざる: total（hard 15 タスクの online 平均 = L&C Table 2 の量）、窓（後期窓 = 本 spec の登録指標）、train 末・test 末（t29 の当てはめと未見画像）。

- **この MLP 箱は L&C の CNN 箱より甘い**: ReLU の total .511 対 L&C .048、腕の幅 .167 対 .675。「5+1 CIFAR で回した」と書くときはこの差を明記しないと読者が彼らの表と直接比べる。
- **test はほとんど差がつかない**: 崩れていない腕で total の幅 .167 に対し test 平均の幅は **.042**。R の test .640 は中位、首位は ELU .670。**測ってきた差はほぼ全部「タスク中にどれだけ速く学べるか」で、汎化ではない。** 原典の指標（可塑性 = 適応の速さ）どおりなので判定は正しいが、「精度が上がる」と読まれる書き方は支持されない。
- **10 倍の更新は暗記を買うだけ**: train 末 .98–1.00 に達しても test 平均は 780 のときとほぼ同じ。
- 扉の腕（CH .573・H .565）は test でも R（.640）より下。

## 8. V11 への意味

- **活性化 → 応答の柱に実ラベルの箱が付いた**（それまで乱数ラベルの 0918 だけ）。KKT1 を代表腕にする根拠（E1）と、L2 Init との対照（E2・E3）が登録。
- **中心化は処方として売らない**。売るのは「H が共通位置の沈下を止める」という機構のレバーで、これは RL-CIFAR（relu_doors）と 5+1 の 2 箱で登録。処方の顔は KKT1。
- **言わないこと**: 「活性化が L2 Init に勝つ」「KKT1 は SNA より良い」「5+1 で文献の順位を再現した」「5+1 の ReLU は fit できなくなる」（適応の速さの喪失。完全死は raw × lr 1e−3）「順位は予算に依らない」「精度が上がる」。
