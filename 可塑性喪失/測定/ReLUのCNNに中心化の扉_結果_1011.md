## 0. 何を測ったか

Kumar らの CNN（conv 3→16 → pool → conv 16→16 → pool → fc 1024→100→100→10）を ReLU にして、RL-CIFAR（1,200 枚・乱数ラベル・400 epoch/課題・batch 16・Adam 1e−3）で、MLP の第一の柱の扉を移した。seed 10–19・30 課題・主窓 t21–30。エンジンは sna_cnn_cause_1009 の束ね。
- **C**: 入力から CIFAR-10 訓練集合のチャネル平均を引く（[[入力を中心化したleakyCNN_結果_1010]] の LRc と bit 同じ前処理）。MLP の C（その seed の 1,200 枚の特徴ごとの平均）とは違う。
- **H**: conv（c1・c2）は pool の後の出力のチャネル平均、fc（f1・f2）はユニット平均を、EMA（β 0.01・勾配なし・訓練と評価で同じ m）で引く。**チャネル平均なので、f1 の入力（16 チャネル × 8×8 位置）の位置ごとの平均は残る**（MLP の H は特徴ごと）。
- **CH**（主）: 両方。**Cr**（対照、seed 10）: 生と同じ大きさの DC を直交方向に残す定数シフト。
- 判定は MLP の扉の規則の移植: 主窓 online ≥ 0.5 の seed が 9/10 以上で RESCUED、1/10 以下で FAIL（床以下が 9 本以上で FAIL_FLOOR）。要約 DOORS は MLP と同じ並び（ref・C・H は救わず CH が保つ）を TRANSFER と呼ぶ。
- 検査 18 項目 all_pass（変異 39/39）。ref の経路は既存の ReLU の CNN の走（cnn_drive_verify_1009/R、seed 10・3 課題）を bit で再現した。

- **登録判定**: ref・C は FAIL。H・CH は **§5.4 (C) の扉の記録が成り立たず `INAPPLICABLE`**、したがって N・DOORS・LAYER も `INAPPLICABLE`。記録の不足（`h_upd` が 30,000 に届かない（課題, 層）が H で 7、CH で 66）は、すべて f1 か f2 の 95〜99% の単位が死んだ層で、その seed の T_f の後に起きた。死んだ単位の m は float32 の非正規数の不動点 7.0×10⁻⁴⁴（0.99·m が m に丸め戻る）で止まり、残る 1〜5 単位は全画像で開いた常時オンの状態だった。規則の免除は「層が全部死んだとき」だけで、ほぼ全滅の層を覆っていなかった（規則の穴。結果を見て規則は変えていない）。
- **事後の読み**（(C) を判定に使わない場合）: 4 腕すべて FAIL、DOORS = **`DOORS_FAIL`**、N = `NONE_RESCUED`、H は `H_LIKE_MLP`、LAYER は `NOT_SHOWN`（H は c1 でなく f1 で落ちる）。
- **CH は崩壊を遅らせるが防がない**: t1–5 は 0.896、t6–10 は 0.727、t11–20 は 0.418 と落ち、主窓では 4 seed だけが床の上（0.12〜0.27）。低下（t1–5 − t26–30）は 0.78（10/10、`RESIDUAL_LOSS`）。
- H 単独は ref より早く落ちる（T_f 2）。C 単独は ref と同じ（Cr も ref の側を通り、C と ref の範囲がどの窓でも重なるので Cr は `CR_UNINFORMATIVE`）。
- EVALOFF は H・CH とも `EVALOFF_DEPENDS`（崩れた後の t30 での小さな差: memo 0.117・0.120 → m = 0 で 0.098・0.104）。
- 同じ seed・同じエンジンの leaky は主窓 LR 0.900・LRc 0.947（記述だけ。活性化が違う）。

## 2. 機構（事後・報告のみ。単位中央値の seed 中央値、初期値 → t）

- **ref と C は c2 から落ちる**（MLP の C の腕と同じ型）。c2 の沈降は µ 経路で、中身は交差項 ⟨ΔW, Δm⟩（t30 で Δz̄ −186・−114）。C は c1 を守る（開いた割合 0.49・死亡 0）が、c2 の入力（ReLU の出力は非負）には触らない。
- **H は c2 を守る**（開いた割合 0.5 前後・死亡 0）**が、f1 が最初に落ちる**。f1 の入力の平均（チャネル平均の中心化で消えない位置ごとの DC）のノルムは t3 で 5.4×10⁴、f1 の Δz̄ は −7.9×10⁴ でほぼ全部が交差項。H では課題 1 から前活性の尺度が大きく育つ（t1 の f1 の幅 1,759 対 ref 9.1、logit の SD 2,019 対 15）。c1 も生の入力の µ 経路で沈む（Δz̄ −68）。
- **CH** は c1・c2・f2 を b 経路で沈め（b の取り分 1.00・0.98・1.00、c1 の Δb −1.78）、**f1 を µ 経路で沈める**（取り分 0.00、交差項 −95〜−338）。f1 の入力の DC の比 r_in は 0.16〜0.41 で、中心化した他の層の入力（c2 0.017〜0.024、f2 0.008〜0.023）より 1 桁大きい。

## 3. 読み

- **「標準の CNN（ReLU）でも入力と中間層の中心化は喪失を防ぐ」は、この形の中心化（色のチャネル平均の C ＋ チャネル平均・ユニット平均の H）では言えない。** 言えるのは「CH は機能の低下を遅らせる（T_f 中央値 3 → 10.5、10/10）が、30 課題の主窓では 4 腕とも床へ落ちる」まで（H・CH の登録ラベルは `INAPPLICABLE`、FAIL は事後）。
- MLP との対応: ref・C が第 2 層（c2）で落ちるところまでは MLP と同じ。違うのは、H が c2 を守った後に **f1（CNN にしかない「位置を持つ入力」を読む fc 層）** が落ちること。チャネル平均の中心化は f1 の入力の位置ごとの DC を残し、それが µ 経路の運び手になった（事後）。MLP の H は特徴ごとに引くので、この経路はもともと無い。
- 言えないこと: f1 の入力を特徴（チャネル × 位置）ごとに中心化すれば防ぐか（MLP の H の厳密な移植。回していない）。c1・c2・f2 の b 経路の沈降を止めれば足りるか（CHB に当たる扉は回していない）。50 課題での振る舞い。

## 4. 予測の採点

- 登録のラベルに対して: Claude は L1 ref FAIL（.93）・L2 C FAIL（.72）・L8 Cr UNINFORMATIVE（.50）が当たり、L3〜L7 は実現が INAPPLICABLE（他の桶 .02〜.07）。二値は 6/12。Fable は L2・L7、Codex は L1・L2・L8 が当たり。
- 事後のラベルに対して（参考）: 3 者とも CH の RESCUED を本命にして外した（CH の FAIL に付けた確率 Claude .14・Fable .15・Codex .11）。H の FAIL は Claude .40・Fable .45 が最頻で当たり、Codex は H の RESCUED .45 を本命にして外した。
