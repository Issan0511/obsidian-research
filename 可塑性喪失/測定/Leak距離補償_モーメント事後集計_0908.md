## 1. 何を確かめたか

Issa の「leak が小さいため、弱い負側は遠くまで動いて寄与を補うのでは」という仮説を受け、正側と負側の前活性量、活性化量、自己二乗の微分モーメントを比較した。

$c=0$、$a=0.1$。各ユニット・各時点で入力支持32点を平均し、

$$P_i=\mathbb E_x[\max(z_i,0)],\qquad N_i=\mathbb E_x[\max(-z_i,0)]$$

を計算した。主な比較は $P_i$ と $aN_i$、$P_i$ と $a^2N_i$。後者は $\mathbb E[\phi_i\phi_i']=P_i-a^2N_i$ に対応するが、実損失の正味更新ではない。

## 2. 出所・標本・集約順

- 実験: act_offset_0906 / LRoff0_1216。
- 10 seed × 100ユニット × 50タスク終端。時点は 4,510,000 から 5,000,000 まで10,000更新ごと。
- 50,000 のユニット・時点イベント、各イベント32入力。**独立標本が50,000あるという意味ではない。**
- 各イベント内で入力平均を取り、その後 seed・時点・ユニットを等重みで平均する。
- 比は**分子の総和／分母の総和**。ユニット別比の平均ではない。
- $v^2$ 付きの比は $\sum_{s,t,i}v_{sti}^2P_{sti}/\sum_{s,t,i}v_{sti}^2a^2N_{sti}$。平均 $v$ を後から掛けていない。
- p の集計は同じ50タスク終端の全ユニット・全入力での割合。条件付き距離は $P/p$ と $N/(1-p)$。
- CI・有意差検定・登録判定は付けていない。仮説を立てたデータの確認であり、別データでの予測検証は残る。

## 3. c=0 の結果

割合は同ファイルの by_seed.positive_share の等重み平均、および [tail_window_description.json](補助データ/Leak距離補償_0908/tail_window_description.json) の LRoff0_1216 行。

| 量                    |          値 |
| -------------------- | ---------: |
| 正側の割合 $p$            | 0.04124125 |
| 正側条件付き距離 $P/p$       |     約1.099 |
| 負側条件付き距離 $N/(1-p)$   |     約3.785 |
| $P$                  | 0.04531077 |
| $N$                  | 3.62878846 |
| $aN$                 | 0.36287885 |
| $a^2N$               | 0.03628788 |
| 活性化量の比 $P/(aN)$      | 0.12486474 |
| 微分モーメントの比 $P/(a^2N)$ | 1.24864740 |
| $v_i^2$ 付き微分モーメント比   | 1.31712492 |

**読めること**: 少数の正側が微分モーメントに強く効く。負側は多数で、条件付き距離も深く、$a^2$ の弱さを人数と距離で部分的に補っている。

**読めないこと**: モーメントが厳密に均衡する、全体の平均位置が静止する、自己項が下降の駆動源である、という結論。正負差は残り、比は1ではない。

### 集団をほどいた結果

同 JSON の groups.all / crossing / all_negative。

| 集計対象      |  イベント数 | $P/(a^2N)$ | 自己項のb方向が上向きの割合 |
| --------- | -----: | ---------: | -------------: |
| 全体        | 50,000 |      1.249 |         77.24% |
| 支持が折れ目を跨ぐ | 18,337 |      4.600 |         37.94% |
| 全点負       | 31,663 |          0 |           100% |

上向きは $P_i-a^2N_i<0$ で定義した**自己項の符号**。実際の $\Delta b_i$ の符号を測った割合ではない。

この条件・窓には全点正イベントが無い。集団での近さは、各ユニット内部での平衡を示していない。跨ぎ群と全点負群の集計も現在状態による記述であり、群間の因果的な力の比較には使わない。

## 4. c=-0.5 の群分けの確認

こちらは**5M単点**・10 seed×100ユニットで、§3の50タスク窓とは異なる。

正側群 = $z_{\min}>0$、跨ぎ群 = $z_{\min}\le0<z_{\max}$、負側群 = $z_{\max}\le0$。出力: [descriptive_groups.json](補助データ/Leak距離補償_0908/descriptive_groups.json) の arm=LRoffm0p5_1216, step=5000000。

| 群   |    割合 | $\bar z$ 中央値 | $\lvert v\rvert$ 中央値 |
| --- | ----: | -----------: | -------------------: |
| 全点正 | 10.2% |    +0.497592 |             0.001225 |
| 跨ぎ  | 53.6% |    −1.659056 |             0.466977 |
| 全点負 | 36.2% |    −2.920812 |             0.559350 |

井戸付近の全点正群は読み出しが小さい。これを「出力を主に担う少数精鋭」と同定する根拠はない。群の存在・適応の必要性は未検証。

## 5. 再構成と検算

記録済みの $\bar z_i$ と自由5ビットの重み $w_{i,\rm free}$ から、

$$z_i(r)=\bar z_i+\sum_{j=1}^5w_{ij,\rm free}(r_j-\tfrac12)$$

で32入力を再構成した。実装の自由ビットは入力末尾5列（15:20）。重みの記録ステップと前活性のステップを対応付けた。

- 再構成した $P_i-a^2N_i$ と記録済み layer1_m_phidphi の最大差は **1.75×10⁻⁷未満**（c=0・今回の窓）。恒等式の検算であり、機構の発見には数えない。
- c=-0.5 の補助的な支持再構成では、折れ目付近の丸めにより微分モーメントに最大0.0140625の差が出た。**その再構成の微分値を本ノートのc=0のモーメント検証へ混ぜていない。** §4の群分けは記録済み zmin/zmax を使用。
- 全ログと縮約ログについて、c=-0.5,0,+0.5 の各seed0、共通時点の zbar/zmin/zmax/v/mob が完全一致。[full_tail_verification.json](補助データ/Leak距離補償_0908/full_tail_verification.json)。
- layer1_zmean を平均活性化とみなしていない。平均活性化は支持上の $\phi$ から計算した。

解析コード: [moment_balance_c0.py](補助データ/Leak距離補償_0908/moment_balance_c0.py)。--data-root で取得先を指定でき、--out でJSON出力先を指定できる。標準のデータルートは次節の場所。

再計算時に10 seed・各50時点と、支持再構成によるモーメント一致を確認する。保存したJSONの主要集計は会話中の初回出力と一致。ログの診断にだけ使った未使用の zmean 比較を再計算コードから除いた。
