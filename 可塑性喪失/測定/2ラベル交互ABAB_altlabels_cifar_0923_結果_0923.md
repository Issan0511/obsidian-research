## 0. 結論（3 行）

1. **ラベルを 2 つで交互にしても第1層のノルムは伸び続ける。伸びは IID の 6 割**（mid2 の登録窓の傾き比 ρ = 0.59、10/10 seed が 0.5–1.5 の区間 = IID_SCALE_GROWTH）。ただし帯で違う: 見える帯ほど減り（top 0.40・mid1 0.44・mid2 0.59・low 0.80）、損失が見ない補空間は減らない（1.24）。伸びは全部が**周期の中心 M の移動**で、A–B の差 D の大きさは伸びない（mid2: ‖M_j‖² の傾き 414 対 IID 698、D_j² の傾き −0.05 対 2.2）。
2. **切替を止めると伸びは止まる**: 同じラベルを 50 課題続ける AAAA は t50 で IID の 26%（Q6 = CONTINUOUS_FIT_LT_80PCT_IID、10/10）。しかも t≈25 以降は 1 課題 0〜1 しか伸びず**凍る**（t2–10 は 600〜800/課題）。理論の「Adam だけの帰無 83–124k」は 4〜6 倍外れ。
3. **再訪は速く、しかも速くなり続ける**: t48 で A を戻すと hit999 まで 400 更新、fresh C は 2,450（比 0.145、10/10、hit_full/hit99 でも同じ）= SAVINGS + STRONG_SAVINGS + FAST_REVISIT。IID 網の t48 の fresh は 4,050 なので、**ABAB 網は IID 網より新しい課題も速く覚える**（事後）。

## 6. spec からの逸脱・注意（summary に載せる約束のもの）

1. **stop 連結は CPU でなく CUDA R=1**（CPU float32 では 1 画像の argmax が閾値をまたぎ、課題長が 500 ずれる。spec §8 に記録、S5 で E-stop15 と厳密一致）。
2. **hit999 は刃の上**（正解数が 1,199 に数百更新座る）。hit_full（1,200/1,200）と hit99（≥1,188）でも Q4 は 10/10・比 0.145/0.150 で同じ。
3. **trace の tc 列**: 本走 5 腕（commit 253b838）は全行に課題終端の tc を書くバグがあり、解析は `tc_at_task_end − 30000 + step` で復元（step 0 で 30000·(t−1) に一致することを確認）。fork は修正後（455d528）で行ごとの tc。修正後の fork が本走の課題 3 を trace 8 列と hit 両方で再現する（S4a）。
4. **中央値の規約**: trace の sig_med は torch.median（下側）、登録の σ_med は snapshot からの numpy 中央値（差 1.7e−5）。
5. LR_abc は launcher の gpu_max がデスクトップの CUDA プロセスを数えて 35 分遅れて起動（別プロセス・同 commit なので結果に影響なし）。
6. 判定は 50 課題内の分類で、有界性や漸近次数の判定ではない（spec §0）。「IID_SCALE」は区間 [0.5, 1.5] の名前で「同じ」の主張ではない（0.59 は下端寄り）。

## 7. 読み（事後、登録外）

- **3 択の答え**: 理論ノート §5 の枠で言えば、ラベル差 D の成分は「有界」（D_j² の傾き ≈ 0）、中心 M は IID の 6 割で伸び続ける（「fresh と同じ」の縮小版）、「IID より速い」は無い。**伸びの担い手は fresh なラベルではなく切替そのもの**: comp（損失が見ない）は ABAB でも IID と同じ速さで伸び（4.7 対 3.9/課題）、AAAA では伸びない（0.1）。見える帯ほど ABAB で減る（top 0.40 → low 0.80 → comp 1.24）ので、IID の伸びのうち「新しいラベルの書き込み」が要る割合は帯の可視度に比例し、残りは切替の衝撃 + 収束後の Adam が運ぶ。
- **Adam だけでは伸びない、ではなく、伸びるが止まる**: AAAA は t2–10 に 600〜800/課題伸び（IID の半分の速さ。損失ゼロで）、t25 で凍る。[[RL-CIFAR第1層の漏れ検査_Adamの三つの歩幅_事後_0922]] の「ε 域 drift ∝ ‖W‖」は AAAA では持続しない。凍る理由（v̂ の減衰か勾配の float32 の床か）は未同定。
- **可塑性喪失の裏返し**: ABAB 網の fresh C（t48）2,450 対 IID 網 4,050。ノルムが小さい網は新しい課題も速い。[[Wの蓄積を止めれば時間劣化は消えるか_結果_0914]] と同じ向き。
- **幅とノルムは別**: ABAB と AAAA は σ がほぼ同じでノルムが 2.2 倍違う。幅は top 帯の N で決まり、top は第 1 の当てはめ後に交互でも続行でも同じ水準（1,227 対 1,301）に止まる。[[RL-CIFAR第1層の幅を広げる者_消し残りと収束後の増幅_事後_0922]] の「幅の定常 σ* ≈ 92」は IID の話で、ABAB は 55 に向かう別の定常（Q5 の閾値 60.1 を下回る）。
- **Snake**: ABAB でも IID でも N は同じ（27.2k 対 26.8k）で、幅は 25.0 対 34.3。leaky の伸びが 6 割に落ちる分は Snake には無い＝ leaky の伸びの 4 割は「新しいラベルの書き込み」で、Snake はそれを最初から捨てている（[[Snakeの幅はなぜ小さいところで止まるか_切替で古い解を捨てる_事後_0922]] の「古い解を捨てる割合 58%」と同じ話）。
- ABC の C₃ +0.46 は Codex の混合予測 (+0.16) を大きく超え、純粋な戻り (+1) の半分。3 ラベルでも「戻る」成分が半分を占める。

## 9. 追記 1（0923 朝、Issa の問い「新しいことなどないはずなのになんで伸びてるのか」・trace の 100 更新刻みで読んだ事後）

**伸びの正体は「毎課題 1 回の Adam の暴発」＋「収束後の静かな漂流」で、ラベルの新しさは要らない。** 数値は seed 中央値、trace の n1 = ‖W₁‖²。

- **課題内の形（ABAB t40、2,000 更新ブロックごとの ΔN）**: 58 / 14 / 14 / 14 / 14 / 15 / 15 / 14 / 13 / 8 / 12 / **554** / 1 / 1 / 1。CE は 6e−4 → 9e−9 まで 2,000 更新ごとに ×0.3 で幾何減衰し、**平均 CE が ~1e−8（float32 の分解能 6e−8 の下）に着いた 22,000–24,000 更新目に 1 回だけ暴発**する。暴発の 100–200 更新で CE は 6e−9 → 1.9〜4.8、正解数は 1,200 → 856〜981（2〜3 割を忘れる）、ΔN は +480〜600。その後 ~500 更新で戻る。
- **課題ごとの内訳（ABAB、hit+500 以降）**: 暴発（100 更新で +100 超）の合計 383（t3）→ 512（t30–40）→ 563（t50）、暴発の位置は 22,700–24,500 更新目で一定、回数 1〜2。静かな漂流は 458（t3）→ 210（t50）と減る。合計 ≈ 760/課題。
- **IID との差は静かな漂流**: IID の暴発は 360–440（ABAB と同じ大きさ）、静かな漂流が 1,200–2,500（fit が浅く CE が 40 倍高い時間が長い。2k 更新目の CE 2.5e−2 対 6e−4）。
- **AAAA が凍る理由**: 暴発の引き金は「float32 で残差 1−p が 0 でない画像が 1 枚は要る」。AAAA では余白の中央値が 10 → 27（t10）→ 59（t20）→ 85（t50）と単調に上がり（暴発のたびの再当てはめが余白を押し上げ、リセットが無い）、**t20 以降は課題の全行で CE が厳密に 0.0** → 引き金が来ない → v̂ と m が減衰し切って歩幅 0 → 凍結（ΔN 0.02/課題）。t5–15 は課題の頭から床にいるので 1 課題に 2〜3 回暴発する（t5 は 877）。
- **切替の役目**: 新しいラベルを書くことではなく、**A の余白を B の間に潰して残差を float32 で見える大きさに戻すこと**。戻れば「幾何減衰 → 床 → 暴発」が毎課題繰り返す。これが「新しいことは無いのに伸びる」の答え。
- **線形（t² でない）理由**: 暴発の向きは引き金の画像と batch 順で毎回違う（増分は互いにほぼ直交、β_all 0.83）。AAAA の増分だけが全ラグで余弦 +0.8（同じ画像が毎回引き金）。
- **測っていないこと**: 暴発の 1 更新の歩幅（3η/座標の上限、[[RL-CIFAR第1層の漏れ検査_Adamの三つの歩幅_事後_0922]] の「全座標 3η の一撃」）と、暴発直前の √v̂ が ε 以下に落ちていること。ckpt t39 からの再生で 1 更新ごとに ‖ΔW₁‖・max|ΔW₁|・非零残差の枚数・min √v̂ を記録すれば決まる（未実施）。
