## 0. 一行

2 ブロックの文字 GPT で、幅の上限 cap は ReLU の網の可塑性の喪失を 10 seed すべてで救った（`CAP_RESCUES`、3 相ともに 10/10、符号検定 p = 0.002）。cap なしの C3-2 は 9/10 seed で追補 6 の 3 条件を満たし、本文の箱の資格を 10 seed で確かめた。

## 1. 走

- 箱：追補 6 の 2 ブロックの箱（n_layer = 2、pre-LN の γ だけ、β・bias なし、Adam lr 1e−3）。箱 M・α 0.01・各課題 10,000 更新・100 課題。fresh は課題 10・25・50・100。
- 腕：C3-2（ReLU）と ReLUcap-2（ReLU＋cap）。cap は「unit ごとの前活性の幅（バッチ分散の移動平均の平方根）が課題 1 末の値を超えたら、up の行を縮めて戻す」介入（Adam の状態・down・γ には触らない、両方の FFN 層）。
- seed 0〜9。本走（4 ブロック）の seed 0〜9 と同じデータ列。
- 走った場所：white-san（seed 0・9）と Vast.ai の RTX 5060 Ti 3 台（seed 1〜8）。各台で、データ列の照合と、C3 の試走（4 ブロック・2 ブロック）が white-san とビット一致することを確かめた。コードは repo 6c80d308、結果は 759c04bd。
- 判定と予測は走る前に spec 追補 7 として commit した（3d7e0544）。

### 2.2 副 1（C3-2 が追補 6 の 3 条件をすべて満たすか）

- 条件 1（学習の成立と喪失）10/10、条件 2（読み出しに隣接する L1 の切替の押しと応答の喪失の先行）9/10、条件 3（切替窓の負の量の L1 への集中と上流の割合）10/10 → すべて 9/10 [測定]。

### 2.3 副 2（届かない型の喪失：ReLUcap-2 の課題 91〜100 の ELast が、同じ seed の新品（課題 100）を上回るか）

- ReLUcap-2 で 6/10（C3-2 は 10/10）[測定]。課題 100 どうしで比べても 6/10。
- 差は小さい。ReLUcap-2 の ELast は 0.082〜0.095、新品は 0.084〜0.088（seed 1 は課題 100 が易しく、新品 0.019・本体の課題 100 は 0.017）。cap の網は崩れないが、新品より少し悪い水準で止まる seed が多い。

## 3. 記録（判定に入れない）

### 3.1 層ごとの死と正側の片側化（固定評価集合、10 seed の平均）

| | 課題 10 | 課題 50 | 課題 100 |
| -- | -- | -- | -- |
| C3-2 の L0 の死 | 0.00 | 0.24 | **0.69** |
| C3-2 の L1 の死 | **0.97** | 0.69 | 0.27 |
| ReLUcap-2 の L0 の死 | 0.00 | 0.00 | **0.00** |
| ReLUcap-2 の L1 の死 | **0.99** | 0.43 | 0.00 |

死は p < 0.005（ほぼ開かない unit）。正側の片側化（p ≥ 0.99）はどちらの腕でも 0.00〜0.08。

- 読み出しに隣接する L1 は、cap があっても課題 10 にほぼ全部死ぬ（L1 の cap は課題 10 ではまだ 7% しか当たらない）。L1 はどちらの腕でもあとで生き返る [測定]。
- cap が効いたのは L0 である。C3-2 は L1 が死んだあと L0 が沈んで死に（課題 100 で 69%）、損失の崩れと重なる。ReLUcap-2 の L0 は課題 10 から全 unit が上限に当たり、死は 0 のまま [測定]。

### 3.2 同じ課題列での 2 対 4（10 課題ごとのオンライン超過損失、seed 0〜9 の平均）

| 課題 | 1〜10 | 21〜30 | 41〜50 | 61〜70 | 91〜100 |
| -- | -- | -- | -- | -- | -- |
| C3（4 ブロック、本走） | 0.094 | 0.118 | 0.121 | — | — |
| C3-2 | 0.150 | 0.238 | 0.458 | 0.560 | 0.790 |
| ReLUcap-2 | 0.154 | 0.203 | 0.210 | 0.135 | 0.123 |

- ReLUcap-2 は課題 50 以降にむしろ良くなる（0.21 → 0.12）。課題の頭 100 更新の損失も、seed 0・1・4 で 1.82 → 1.22 と良くなった [測定]。

### 3.3 L1 の生き返りについて（seed 1000 の下見と seed 0・1・4 での事後の観察、1 seed ずつ）

- C3-2 の 4 seed すべてで、L1 は L0 が沈むのと同じ時期に生き返った。ReLUcap-2 では L0 が沈まなくても生き返った [測定]。
- 生き返る時期に、L1 の有効な読み出し（W_down の列を最終 LN の入力の rms で割って読み出しを通した大きさ）が半分以下に縮んでいた（5 本すべて）。**訂正（1021）**: LN が実際に割るトークンごとの標準偏差で測ると、縮みは約 2 割（seed 1000 で 1.19 → 0.96）で、分母の膨らみは W_down の伸びに大半打ち消される。[[文字GPTで継続学習_2ブロックのL1の生き返りを介入で分ける_1021]] §4。最終 LN の入力を膨らませたのは、生き返りつつある L1 自身の出力（FFN1、rms 9 → 83）で、FFN0 と注意 1 はほぼ一定だった [測定]。生き返り → 共通の書き込み → 分母が膨らむ → 読み出しが縮む → 押しが弱まる、という正の帰還に見える [読み]。
- 生き返った unit の μ/σ の変化を入れ替えで割ると、上流の分散の伸びが 3 本とも浮かせる側に効き、上流の平均と自分の重み（probe では開かないが学習の流れでまれに勾配が入る）が網ごとに加わった [測定]。
- 介入の結果（1021）は [[文字GPTで継続学習_2ブロックのL1の生き返りを介入で分ける_1021]]。読み出しを縮めると 1 課題で生き返り、FFN1 が分母を膨らませる経路を塞ぐと生き返らなかった。
