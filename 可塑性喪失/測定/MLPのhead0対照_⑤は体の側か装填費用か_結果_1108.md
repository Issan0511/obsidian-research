# MLP の head0 対照 — ⑤は体の側か、装填の費用か（結果、1108）

依頼: [[V13_ViT箱のすり合わせ_段①〜⑤_1029]] の続き。ViT 箱では課題 30 までの遅れが全部 head の側だった（head を 0 に戻すと新品より速い）。MLP で同じ対照を取り、段⑤「沈んだ unit は応答を失い、学び直しが削れる」を「読み出しへの経路がその層だけのとき」の前提つきで残せるかの材料にする。
箱: 1 隠れ層の乱数ラベル MNIST（784-100-10、Adam 1e-3・batch 16・4,000 更新/課題・30 課題、engine は push_direction_proof_0930、再生はビット一致）。活性化 leaky 0.1・ReLU・ELU・SiLU・GELU × seed 0・1。
腕（切替ごと、同じラベル・同じミニバッチ順）: 継続 S、head を 0 に戻す H0（重みと bias と head の Adam を 0、体はそのまま）、H0A（H0 に加えて体の Adam も 0）、新品 fresh。
主量: 漸近（更新 3,510〜4,000）の訓練精度の比 ρ_A = (新品 − H0)/(新品 − S)。1 なら head を替えても戻らない（体の側）、0 なら新品に並ぶ（切替の事件の側）。判定は課題 21〜30、帯は取り直しのばらつきから。
記録: lop_analysis `specs/spec_head0_mlp_1108.md`・`results/head0_mlp_1108/`（summary.md・judge.md・early_switches.md・posthoc/bodystep.md・図 `fig_head0_mlp_1108.png`）。生データは `obsidian-research-data/head0_mlp_1108/`。

## 結論（3 行）

1. head だけ 0 に戻しても、課題 21〜30 の漸近の遅れは leaky・SiLU・GELU で 7〜9 割、ReLU で全部残る（体の側）。ELU だけ 6 割が戻る。
2. head に加えて体の Adam 状態も 0 にすると（H0A）、leaky は新品と同じ漸近に着く。ELU は 8 割、SiLU は 3 割、GELU は 2 割が戻り、ReLU は戻らない。「体の側」は、leaky・ELU では体の重みでなく、体の optimizer 状態と閉じた unit が開き直す時間の側だった。
3. 早い課題（3〜10）では 5 活性化とも遅れはほぼ全部切替の事件で、前の課題への装填 log K − L が強いほど ρ_A は 0 に近い。課題が進むと体の側へ移る。ViT の「課題 30 は head 側、課題 60 は体の側」と同じ順。

| leaky 0.1 | 0.760 / 0.726    | BODY_SIDE           | 1.32 / 1.26 | 体の側・H0 は S より遅い | 0.58 / 0.69 / 0.98 / 0.99 |

- 帯（±2SE）の幅は 0.003〜0.009。T90（0.9 に届く更新）は S・H0 とも 10/10 届かず、新品は 10/10 届く。
- スパイク（更新 0〜4 の損失）は H0 で 5 活性化とも新品と 0.015 nat 以内（S は +0.64〜+2.29 nat）。
- H0k（ViT の R0 と同じ約束で head の Adam を残す）と H0 の差は 0.013 以下。

## 体の中で何が動いたか（課題 21〜30 の平均）

| 活性化       | 死んだ unit の割合（p⁺ < 0.005）課題頭 | 課題末 S | H0   | H0A  | 新品   |
| --------- | --------------------------- | ----- | ---- | ---- | ---- |
| leaky 0.1 | 0.55                        | 0.56  | 0.10 | 0.00 | 0.00 |
| ReLU      | 1.00                        | 1.00  | 1.00 | 1.00 | 0.18 |
| ELU       | 0.27                        | 0.27  | 0.09 | 0.01 | 0.00 |
| SiLU      | 0.87                        | 0.88  | 0.44 | 0.36 | 0.00 |
| GELU      | 0.95                        | 0.95  | 0.65 | 0.59 | 0.00 |

- S では閉じた unit は課題の中で開き直らない。H0 では開き直るが遅く途中まで、H0A では leaky・ELU で全部開き直る。
- H0 が更新 1,000 で S より遅い理由は体の Adam の v（課題 25 の記録）。更新 1〜100 の体の勾配は H0 と H0A で同じ大きさなのに、体の 1 更新の変位は H0 が H0A の 0.07〜0.31 倍。v は前の課題の値のまま（H0A の 100〜250 倍）で、更新 1,000 でも 6 割残る。
- H0 が戻せる割合（leaky 0.26・ELU 0.62・SiLU 0.10・GELU 0.08・ReLU 0）は、切替時に生きている unit の割合（0.45・0.74・0.13・0.06・0）と順位が一致する（事後の読み）。

## 予測の採点

送り手（Vit振り返り、Fable）: ReLU 全滅後は体の側 ○、leaky 0.5〜0.8 ○、ELU ≥ 0.7 ×（0.38）、SiLU・GELU は間 ×（leaky より上）、スパイク消える 割れ（値は 5 つとも消えている）、H0A は速くならない ×（大きく上）。
受け手（このセッション、Fable）: ρ_A は leaky・ReLU・SiLU・GELU ○、ELU ×。ρ_1000 は ReLU だけ ○（leaky・SiLU は H0 が S より遅い）。H0A との差 ≤ 2σ は ×。

## 段⑤への材料（置き方は Issa の判断）

- MLP では head を 0 に戻しても遅れは 4/5 の活性化で残る。ViT では残らなかった。
- 残る遅れの担い手は、SiLU・GELU・ReLU では φ′ ≈ 0 の unit（体の重み）。leaky・ELU では体の optimizer 状態と閉じた unit が開き直す時間で、体の重みそのものは head と Adam を新しくすれば新品並みに戻せる。
- 言わないこと: H0・H0A を手法として語らない。この箱の値を CNN・ViT へ一般化しない。ρ_A < 1 の分を装填の費用と切替の押しに分けない（H0 では同時に消える）。箱 2（RL-CIFAR MLP）は別の段。
