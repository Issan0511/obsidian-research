## 旧走1 — 5+1の一回ReDo × 位置回復

run id: `redo_position_2x2_1018`。F51/std/ReLU、seed0–9。task28末で一回介入し、**task29のonline精度**を比較した。

| 腕     | 平均online精度 |
| ----- | ---------: |
| none  |   40.4235% |
| redo  |   55.5805% |
| shift |   52.7143% |
| both  |   55.9647% |

ReDo単独とshift単独はいずれもnoneより改善したが、登録した**POSITION_CARRIESは成立せず、MIXED**。both−shiftは+3.2504 pt、同時区間[+0.3739, +6.1269]。both−redoは+0.3842 pt、同時区間[−0.2064, +0.9748]。同時区間は登録した7比較のBonferroni補正による。

ReDoは閾値τ=.1で選び、完全死亡unitだけを対象とする操作ではない。shiftは介入前に生きていた第2隠れ層unitのbiasを一様に持ち上げる。この走は一回介入であり、以前の周期ReDoとは別プロトコル。**新走の結果で旧走の予測不成立を置き換えない。**

## 走2 — cap12の活性化 × 箱

run id: `cap_act_box_2x2_1018`。RC/stdとF51/std、ELUとReLU、seed0–9。cap12はtask1末のW1/W2のunit別行ノルムを上限とし、task2から毎更新後に射影する。biasやAdam momentを同時には射影しない。

主窓は**RC: task31–50、F51: hard課題21/23/25/27/29**。以下はcap12−refの平均対応差。

| セル       |       cap差 | 8比較の同時95%区間                 | 登録上の扱い                         |
| -------- | ---------: | --------------------------- | ------------------------------ |
| RC/ELU   | +75.889 pt | [+74.908, +76.869]          | HELP                           |
| RC/ReLU  |  約0.000 pt | [−0.0000175, +0.0000133] pt | 方向判定UNRESOLVED、別判定は±0.5 pt内で同等 |
| F51/ELU  |  −1.999 pt | [−2.495, −1.504]            | NO_RESCUE、HARMあり               |
| F51/ReLU |  −3.601 pt | [−7.696, +0.494]            | UNRESOLVED                     |

全体は**MIXED**。予測ACTIVATION_SPLITSは成立しなかった。RC/ELUの改善をF51/ELUへ一般化できない。RC/ReLUの同等性を、方向判定NO_RESCUEへ勝手に変更しない。F51/ReLUは平均が低くても、登録同時区間が0をまたぐため悪化確定ではない。

F51/ReLUの追加対照cap12b・lr_onlyによる登録分離判定も**SEPARATION_UNRESOLVED**。lr_onlyは較正時の相対変位RMSに合わせた対照であり、評価時の全実効学習率が厳密一致したとの主張ではない。既知のRC/ELU等の再走を、新しい独立予測の成功として数えない。

出所: `results/cap_act_box_2x2_1018/verdict.json` の `cells[RC/ELU, RC/ReLU, F51/ELU, F51/ReLU]`（mean/lo/hi、m=8）および `separation.labels`、同runのspec §2.2。結果・追試を含むローカルcommit: `a6703eae1cd0e9cab5287df0c6b978020d919659`。

## 走2の事後追試 — capのfresh費用を切り分ける

**元の結果を見た後の事後追試。** Issaの「Capのfreshが悪かったわけではないん？」「切り分けて」に対応した。新しいfresh-capの結果取得前に条件を固定したが、元実験とは独立な事前登録再現とは数えない。

F51/ELU・ReLU、seed0–9、hard課題21/23/25/27/29を各々freshから学習。同じ初期重み、元のtask1末cap半径、画像・ラベル・バッチ列を対応させた。初期射影はせず、最初のAdam更新後からcapを適用する。

| 活性化  | fresh capなし | fresh capあり | 継続 capなし | 継続 capあり |
| ---- | ----------: | ----------: | -------: | -------: |
| ELU  |     65.354% |     65.298% |  64.613% |  62.613% |
| ReLU |     65.027% |     64.991% |  43.661% |  40.059% |

| 活性化  | freshでのcap差                | 継続でのcap差                   | 交互作用（継続差−fresh差）           |
| ---- | -------------------------- | -------------------------- | -------------------------- |
| ELU  | −0.056 pt [−0.084, −0.028] | −1.999 pt [−2.469, −1.529] | −1.943 pt [−2.416, −1.471] |
| ReLU | −0.036 pt [−0.073, +0.002] | −3.601 pt [−7.486, +0.283] | −3.565 pt [−7.450, +0.319] |

角括弧はこの追試の**6比較のBonferroni同時95%区間**。元の8比較の区間と混ぜない。継続側は元データを使っており、独立な継続学習seedを増やしたものではない。

**ELUの継続での約2 ptの悪化は、freshの約0.06 ptの費用だけでは説明できない。** matched fresh gapはcapなし0.741 pt、capあり2.685 pt。履歴との交互作用はあるが、具体的な幾何・optimizer機序までは同定していない。ReLUは継続差・交互作用の区間が0をまたぎ、追加悪化は未確定。

## 走6 — CNNのCH′＋現在幅に応じたbias抑制

run id: `cnn_chprime_bias_1018`。RC/raw/ReLUのCNN、30課題、seed10–19。CH′のconv特徴はチャネル×位置ごとにEMA中心化する。追加Bは毎Adam更新後、c1/c2/f1/f2のbiasを**現在のミニバッチ幅の±0.2倍**へ射影する。WとAdam momentを射影せず、出力biasも対象外。

主窓は**task21–30のonline平均**。

| 腕          | 平均online精度 | seed内窓精度が50%以上 |
| ---------- | ---------: | -------------: |
| CHf（CH′対照） | 49.518159% |           6/10 |
| CHf_B      | 94.155079% |          10/10 |

主判定は**RESCUED**で予測と一致。CHf_Bのseed別窓精度は91.5516〜95.6409%。対応差は+44.636920 pt、通常の95%t区間[+23.094608, +66.179232]、全10seedで改善、両側正確符号検定p=0.001953125。

旧P183はcudnn TF32=trueで、今回のTF32=falseと異なるため比較対照を再走した。CPU検査と実GPU検査を通過。生データの退避・SHA256照合済み。

**30課題での救済**であり、200課題・無期限の維持や4層のどのbias操作が必要だったかは未分離。

出所: `results/cnn_chprime_bias_1018/verdict.json` の `primary.mean_W/W/window_tasks/kept` と `secondary.mean/ci95/sign_p`。CHf・CHf_Bの `per_task.csv`（seed10–19、task21–30、online_acc）を再集計して平均・50%以上の個数を照合。ローカル結果commit: `c4e3bbd1640e1f5b05476a8b0386fde6a53d9702`。
