## 3. 数値計算の効率規則（ローカル 1 台・ほぼ直列）

**実測の規模感**: 5M × 10 seed × 1 腕 ≈ **28 分**（`centered_freeze_0901` provenance 1655.9 s・w100 1 層）。`LR_A1` 級 ≈ 15 分。P-2（幅 5 × 3 活性化 × seed 20 × 5M）は粗く 1–3 時間級。**つまり律速は計算機の速さではなく、再走事故と段取りである。**

1. **★ 再走を潰す spec 前チェックリスト**（今月の全 spec で毎回通す。効けば [[運用ルール]] §5 へ昇格）
	- [ ] 新 seed 群は `generator_offset` で作る（`--seeds` だけでは bit 一致の同一系列 — T0b の事故）
	- [ ] 吸収・凍結のある系は**総和と率の両方**を endpoint に書く（教訓⑰）
	- [ ] **等価限界 Δ を事前登録**する（「CI が 0 を含む」を「タイトな null」と「判定不能」に分ける — 保持測定の教訓）
	- [ ] 二値 endpoint の飽和を事前検討（教訓⑪。幅 5 は `dead_frac` 分解能 0.2 → `eval_loss` 主体・seed 20+）
	- [ ] studentized fallback と退化ガード（教訓⑬）／窓ラベル（⑫）／マスク個数の検算（⑭）／step 0 過渡（⑮）
	- [ ] 未フィット率の床の継承元を明示（2 層系 1e-23・1 層系 1e-16）
	- [ ] ロガー相乗り（下記 2）を spec 起草時に検討したか
2. **ロガーを盛ってから回す。** `M`・`B`・`denom`・`submerged`・per-layer 統計・境界スナップを新規走の既定にする。再計装リプレイ 1 回 ＝ 新走 1 本ぶんの時間。8/31–9/1 の走なし解析ラッシュ（`layer_stats.csv` 直読み等）が効いたのはログが厚かったから。**ただし主判定は spec の 1 つ**（相乗り列は事後ラベルで使う）
3. **3 commit 構成を厳守**: spec 単独 commit → 実装 → 結果（`gate_dose_0830` 型）。`centered_freeze_0901` は 1 commit に畳まれた（`elu_swamp` と同型・チャットログで時系列は追える）— **次からは崩さない**
4. **seed のプロセス並列（任意・効けば数時間級バッチが 30 分級になる）。** per-seed 独立プロセスなら決定論は壊れない。`OMP_NUM_THREADS=1` を全プロセス共通に固定したまま、runner の seed ループの外側に並列を足すだけ。**導入条件: 既存走 1 本（例: `centered_freeze_0901` frozen 腕）の bit 一致再現を先に確認する。** P-2（60 seed-run 級）の前に入れると一番効く
5. **キュー運用**: 回すと決めた走は前夜までに spec を凍結し、朝一・離席前・就寝前に投入する。1M パイロットは「パイロット」と spec に明記（**確証走は 5M 直行** — 1M の見かけ事故 2 回の教訓）
6. **★ 長い走ほど早く投入する（9/1 追加・Issa）。** 走の長さは「後回しにしてよい理由」ではなく「**先に投入すべき理由**」である。M 級（1 時間超）の走は、判定・書き物より**先に**キューへ入れ、走行中に走なしレーンへ移る。週の後半に回すと、判定が想定外の分岐に落ちたときの追走枠が消える。**優先順の判断で「走なしの作業が先に片付くから」を理由に M 級を後ろへ送らない**
