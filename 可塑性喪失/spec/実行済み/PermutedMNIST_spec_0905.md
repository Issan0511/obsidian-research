## 0. 一行

**まず対照（ReLU）が Permuted MNIST で「dead unit ＋ノルム成長」という今日の機構で壊れているかを確かめ（段 0・足切り）、壊れていなければ止める。** 壊れていたら Snake を入れて、(P1) 沈下を防ぐか・(P2) それが精度保持に化けるか、を分けて判定する。

## 1. なぜ回すか

| 材料 | 出所 | 格 |
|---|---|---|
| Snake は深さ 1・深さ 2・幅 5 のすべてで沈まず、‖w‖ が唯一 1 を下回る | [[前活性の力学_事後_0904]] §8.1・8.3・8.5 | **未登録・事後** |
| lr 交絡ではない（対照を lr 0.005/0.002 に下げても沈むし劣化する） | 同 §8.3 | 未登録・事後 |
| 線形だからでもない（α=30/100 は解けない・幅 5 で LIN5 に 20/20） | 同 §8.4・8.5 | 未登録・事後 |
| 機構: ReLU 族の `mobility` は深さの単調減少関数（ReLU 中央 0.0000・ELU 0.0060）。Snake は深さに依らず 1 のまわり | 同 §8.6 | 未登録・事後 |
| **しかし適合では leaky に勝てない。** 幅 5 で符号 6/20（p=0.115）、差の大きさでは leaky が上 | 同 §8.5 | 未登録・事後 |
| 幅 5 では leaky が −4.68 まで沈みながら Snake と同等以上に適合する = **沈下が性能を悪化させていない** | 同 §8.5 | 未登録・事後 |

**動機**: 「沈まない」は 3 設定で立ったが、「だから性能が良い」はどの設定でも示せていない。合成箱の中では**沈下が性能に結びつく領域に入れていない可能性**があるので、外へ出す。Permuted MNIST を選ぶのは、**失敗機構が今日の話と同型と報告されている**（dead unit 割合と重みノルムの単調増加）唯一の標準ベンチだからである。

### 1.1 先に書いておく危険（登録判定に先回りする）

1. **対照がそもそも今日の機構で壊れていないかもしれない。** Permuted MNIST の LoP は報告されているが、われわれの MLP・step 数・タスク数でそれが再現するとは限らない。**再現しなければ Snake を入れても何も言えない。** → 段 0 を足切りにする（§5.1）
2. **今日の幅 5 と同じ結末になりうる。** 「Snake は沈まないが leaky と精度が変わらない」。これは**失敗ではなく結果**なので、ラベルとして先に用意する（`SINKING_NOT_BINDING`）
3. **Snake が発散する。** 深さ 2 で α に非単調・幅 5 で 20 seed 中 1 本の発散で腕ごと脱落した。**実データでは lr も ‖J‖² も違う**ので、段 1 の lr 較正を独立に置く
4. **先行研究が既に試している可能性。** Snake は Ziyin et al. (2020) の既存関数である。**回す前に文献確認を済ませること**（§9-1）

## 2. 何を測るか

### 2.1 軸

**活性化のみ**を動かす。ネットワーク・データ・タスク列・seed・最適化器は全腕で同一にする。lr だけは §4.2 の登録規則で腕ごとに決める（`‖J‖²` が 3–7 倍違うので同一 lr は公平でない）。

### 2.2 腕

| 記号 | 活性化 | 役割 |
|---|---|---|
| `R` | ReLU | **主対照**。段 0 の足切りはこの腕で判定する |
| `LR` | leaky ReLU (a=0.1) | **本命の対抗馬**。幅 5 で Snake を上回った腕 |
| `SN3` | Snake (α=3) | 主対象。3 設定すべてで生き残った唯一の α |
| `SN1` | Snake (α=1) | REPORT_ONLY。α 依存を見る。発散を許容する |
| `LIN` | 恒等 (φ(z)=z) | 下限。線形ネットの精度と沈下ゼロの基準 |

### 2.3 本走が答えないこと

正規化（BatchNorm/LayerNorm）あり・Adam・CNN・Continual ImageNet・α のスイープ・初期化スケールで ‖J‖² を揃える設計・reset 系の介入（CBP など）との比較。**Snake が実務で使えるかも答えない。**

## 3. スコープと前提

- **データ**: MNIST。訓練 60,000 から**タスクごとに固定の 10,000 例**を層化抽出（クラス比を保つ）。評価は test 10,000 の全部
- **タスク**: 784 画素の置換を 1 タスク 1 個。**200 タスク**。置換は seed から決定的に生成し、全腕で同一列
- **ネットワーク**: 784–100–100–10 の MLP、bias あり、出力は線形。**深さ 2・幅 100 は合成箱の深さ 2 設定に合わせた意図的な選択**（§8.3 と地続きにするため）
- **最適化**: 素の SGD、batch 16、1 タスク 1 エポック（= 625 step/タスク、計 125,000 step）。**モーメンタムなし・weight decay なし・正規化なし**。これは今日の機構が成り立つ条件を保つための選択で、実務的な強さを狙っていない
- **損失**: cross-entropy
- **seed**: 0–9（10 本）。seed は init・データ抽出・置換列・batch 順を決める
- **タスク間でオプティマイザ状態も重みもリセットしない**（これが continual の定義）

## 4. 設計

### 4.1 段 0 — 機構の足切り（`pmnist_probe_0905`・3 腕・50 タスク）

`R` / `LR` / `LIN` を 50 タスクだけ回し、**対照が今日の機構で壊れているか**を見る。Snake は入れない。

### 4.2 段 1 — lr 較正（`pmnist_lrcal_0905`）

**同一 lr は公平でない**（‖J‖² が 3–7 倍違う）。腕ごとに lr を選ぶ。

- 格子: lr ∈ {0.2, 0.1, 0.05, 0.02, 0.01, 0.005}（登録・6 点）
- 手続き: 各腕・各 lr で **seed 0–2 のみ・20 タスク**を回す
- 選択規則（登録）: **発散しない（全 seed で有限）lr のうち、タスク 1–20 の平均 test 精度が最大のもの**。同点なら大きい lr
- **選択は段 2 の評価窓（タスク 151–200）を一切見ない。** 段 1 と段 2 は seed も分ける（段 1 は 0–2、段 2 は 0–9 で、重なる 3 本は段 2 で再走する）

### 4.3 段 2 — 本走（`pmnist_main_0905`・5 腕・200 タスク・seed 0–9）

> **改訂あり → §10.3。** lr が支配軸だったので、単一の較正 lr ではなく lr 面（5 腕 × 5 lr × 10 seed）を回す（2026-09-05・Issa 裁定）。

段 0 が `MECHANISM_PRESENT` を出したときだけ回す。

### 4.4 測る量

タスク終了ごとに記録する。

**性能**: 当該タスクの test 精度（学習直後）。**主要 endpoint はこれ。**
**機構（今日の量の実データ版）**:
- `dead_frac`: 各層で、当該タスクの test 集合にわたり出力が常にゼロ（ReLU）または `|φ'| < 1e-6`（一般）のユニットの割合
- `w_norm`: 層ごとの重み行ベクトルのノルムの中央値
- `zbar`: ユニットごとの前活性の test 集合平均、その中央値
- `mobility`: ユニットごとの `E_test[φ'(z)]`、その中央値。**§8.6 のとおり `φ'(z̄)` ではなく平均を取る**
- `eff_rank`: 隠れ層活性の実効ランク

## 5. 登録判定

### 5.1 段 0（足切り）— `M0`

| 条件（すべてタスク 1–50・10 seed 中央値） | ラベル |
|---|---|
| `R` の test 精度が **タスク 1 の値から 2 %ポイント以上**下がり、**かつ** `dead_frac` が 0.10 以上増え、**かつ** `w_norm` が 1.2 倍以上になる | **`MECHANISM_PRESENT`** → 段 1 へ |
| 精度は下がるが `dead_frac` と `w_norm` の条件を満たさない | **`LOP_BY_OTHER_MECHANISM`** → **止める。** 今日の機構では説明できないので Snake を入れる根拠がない |
| 精度が下がらない | **`NO_LOP_IN_THIS_SETUP`** → **止める。** タスク数か step 数を増やす設計変更が先 |

**止める判断を先に登録しておくのが本 spec の主眼である。** 段 0 で落ちたら段 1・段 2 は回さない。

### 5.2 段 2 — `P1`（沈下を防ぐか）

> **改訂あり → §10.2。** `dead_frac` は微分に床のある腕では恒等的に 0 なので、P1 の 3 指標は `zbar`・`mobility`・`w_norm` に差し替えた（2026-09-05・Issa 裁定）。

評価窓 = **タスク 151–200**。`SN3` と各対照の `zbar` 中央値・`dead_frac`・`w_norm` 比を seed ごとに対応させ、符号検定（n=10・両側）。

| 条件 | ラベル |
|---|---|
| `SN3` が `R` と `LR` の両方に対し、3 指標すべてで 9/10 以上かつ p<0.05 | **`SNAKE_DOES_NOT_SINK`** |
| 一部の指標・一部の相手のみ | **`PARTIAL`** |
| どちらにも立たない | **`SINKS_LIKE_RELU`** |

### 5.3 段 2 — `P2`（精度に化けるか）**主判定**

評価窓 = タスク 151–200 の平均 test 精度。seed ごとに対応させ、符号検定（n=10・両側）。**同時に対応のある差の平均と標準誤差も出す**（§8.5 で符号検定が差の大きさを捨てて読み違えたため。**両方を先に登録しておき、事後に選び直さない**）。

| 条件 | ラベル |
|---|---|
| `SN3` > `LR` が符号検定で有意（9/10 以上・p<0.05） | **`SNAKE_RETAINS_BETTER`** |
| `SN3` と `LR` が差なし、かつ **P1 が `SNAKE_DOES_NOT_SINK`** | **`SINKING_NOT_BINDING`**（今日の幅 5 と同じ結末。沈下は防げるが性能に効かない） |
| `SN3` < `LR` が有意 | **`SNAKE_WORSE`** |
| `SN3` が発散して腕が落ちる | **`SNAKE_DIVERGED`** |

**`SINKING_NOT_BINDING` は失敗ではなく結果である。** これが出たら「沈下は LoP の原因ではなく随伴現象」という読みが実データでも支持されたことになり、そちらを主張として書く。

### 5.4 REPORT_ONLY

`SN1` の全指標、`LIN` との比較、`eff_rank`、層別（第 1 層 vs 第 2 層）の差、段 1 で選ばれた lr の一覧。

### 6.2 Claude（2026-09-05・走らせる前に記入）

- **M0 = `MECHANISM_PRESENT`（確信 中）。** Permuted MNIST の LoP は報告されているが、われわれの 200 タスク・batch 16・幅 100 で 3 条件すべてを満たすかは自信がない。落ちるとしたら `w_norm` 1.2 倍の条件

## 7. 検査（新規・既存は 1 つも継承できない）

- **S-data**: MNIST の sha256 を記録。タスクごとの抽出が層化されており、クラス比が全タスクで ±1% に収まる
- **S-perm**: 置換列が全腕で bit 一致する（seed から決定的）。置換が恒等でない・重複しない
- **S-init**: 同一 seed で全腕の初期重みが bit 一致する（活性化は RNG を消費しない）
- **S-act**: `φ` と `φ'` を解析式と実装で `np.allclose(atol=0)` 照合（[[前活性の力学_事後_0904]] §5 と同じ流儀）。Snake は φ' = 1+sin(2αz)
- **S-mob**: `mobility` が `E_test[φ'(z)]` であり `φ'(z̄)` でないことを、両者が桁で違う例で確認する
- **S-div**: 非有限が出たら腕ごと落とす。救済しない。検出 step と seed を記録
- **S-repro**: 段 2 の `R` を 1 seed だけ再走し、logs が bit 一致する
- **S-cost**: 段 0 の前に 1 腕 5 タスクの壁時計を測り、段 2 の総時間を見積もって §9-4 に報告する

### 10.2 §5.2 `P1` の指標を差し替え（裁定 2026-09-05）

**不具合**: `dead_frac` は `|φ'| < 1e-6` 定義なので、微分に床のある腕（`LR` a=0.1・`SN3`・`SN1`・`LIN`）は**構成上つねに 0** である。段 0 の全タスク・全 seed・全 lr で `LR` の `dead_frac` 最大値は 0.0000 だった。P1 は `SN3` が `LR` に 3 指標すべてで 9/10 以上を要求するので、`dead_frac` は 10 seed 全部が 0 対 0 の引き分けになり、**`SNAKE_DOES_NOT_SINK` は何が起きても到達不能**（必ず `PARTIAL`）。

**改訂**: P1 の 3 指標を **`zbar` 中央値・`mobility` 中央値・`w_norm` 比**とする。`mobility` は全活性化で定義でき、§8.6 の機構主張そのものの量である。段 0 で 3 腕を明確に分離している（`R` 0.0075 / `LR` 0.108 / `LIN` 1.000）。**`dead_frac` は `R` 専用の REPORT_ONLY に降格**（§5.4 へ移す）。§5.1 の M0 は `R` 単独の判定なので**改訂の影響を受けない**。

### 10.3 §4.3 段 2 を lr 面に拡張（裁定 2026-09-05）

**理由**: lr がこの箱の支配軸である。ピーク−最終は lr 格子上で 0.000 → 0.071 動くのに対し、lr を固定したときの `R`–`LIN` の差は 0.044 → 0.015 でしかない。§4.2 は腕ごとに lr を選ぶので、Snake が 1–2 段低い lr に較正されると（実測: `SN3`・`SN1` とも lr=0.2 で発散、0.1 では完走）、**精度差の大半が lr 差になる**。§引用制限の最終行が言葉で警告していた穴に、段 0 が数値を与えた。

**改訂**: 段 2 を **5 腕 × lr {0.1, 0.05, 0.02, 0.01, 0.005} × seed 0–9 × 200 タスク**（250 run）で回す。§4.2 の選択規則が選ぶセルはこの面の部分集合なので、**登録どおりの主判定（P2）はそのまま出せる**。加えて **lr を揃えた 1 軸比較**（§8.5 の流儀）が同じ走から取れる。両方を出し、**事後に選び直さない**。

### 10.4 §4.1・§5.1 について（裁定待ちではない・記録）

- **§4.1 は段 0 の lr を登録していなかった。** 段 1 が段 0 の後に来る以上、段 0 は自分で lr を選ぶしかない。選定の記録は `summary.md` の lr 走査表（腕 `R`・seed 0–2・9 点・200 タスク）。**§4.2 の登録済み選択規則（タスク 1–20 の平均精度が最大）は `R` に lr=0.1 を選ぶ**（0.9134 対 0.05 の 0.9128・0.2 の 0.9022）ので、段 0 の主報告もそこに置いた。
- **段 0 は 50 タスクでなく 200 タスクを回した。** 50 タスクはその前置きなので情報は失われない。逆に lr ≤ 0.02 ではタスク 50 時点でまだピークに達しておらず、50 で切ると誤った理由で `NO_LOP_IN_THIS_SETUP` と読める。
- **§5.1 の精度条件はタスク 1 を基準にしている。** lr ≲ 0.05 ではタスク 1 自体が立ち上がり途中なので、この条件は「失われた量」ではなく「タスク 1 がどれだけ良かったか」を測る。**lr=0.1 のラベルは登録どおりの基準で立っている**が、ピーク基準に変えると LoP は lr=0.01 から出て単調に増える（0.009 → 0.024 → 0.040 → 0.054 → 0.071）。両方を `verdict.csv` に出してある。**この節は改訂ではない。M0 のラベルは登録どおりの基準のもの。**
- **lr=0.001 は機構が消える側だった**（Issa が 9/5 に提案・実測で否定）。タスク 1 の精度が 0.154 で、625 step では 1 タスクも適合できない。200 タスク走らせてもまだ登り坂（ピークがタスク 198）で、`mobility` 0.982・‖w‖ 1.23 倍と機構量が動かない。

### 10.5 §9-1 の文献確認（実施済み・2026-09-05）

### 10.6 §7 の検査（全通過・`results/_checks_pmnist_0905/checks.json`）

- **`dead_frac` を非 ReLU 腕の指標として引かない。** 微分に床のある活性化では構成上つねに 0 であり、「Snake は死なない」の証拠にならない（**恒真**）。§10.2
