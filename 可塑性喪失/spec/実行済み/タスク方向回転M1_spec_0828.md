## 0. 問いと主判定

各 seed s・実境界 B について、前後タスク方向の余弦

\[
c_{sB}:=\hat\mu_{s,B}^{-}\cdot\hat\mu_{s,B}^{+}
\]

と、その境界での再分類死率 `r005_sB` の関連を見る。

予言は

\[
\operatorname{corr}(c_{sB},r005_{sB})<0
\]

である。c が小さいほど回転角が大きく、その境界で死ぬ割合が高い、という向き。

主推定量は seed ごとの Spearman 相関 `rho_s` を計算し、10 seed を等重みで平均した

\[
\bar\rho=\frac1{10}\sum_s\rho_s
\]

とする。

| 95% seed-cluster bootstrap CI | `M1` 判定 |
|---|---|
| CI 上端 `< 0` | `NEGATIVE_ASSOCIATION` |
| CI 下端 `> 0` | `OPPOSITE_ASSOCIATION` |
| CI が 0 を含む | `INCONCLUSIVE` |

等価域は置かない。`INCONCLUSIVE` を「関連なし」と書かない。

## 1. c_B の閉形式

`f_T∈{0,1}^15`、`n_T=sum(f_T)` とすると

\[
\mu_T=(f_T,0.5\mathbf 1_5),\qquad \|\mu_T\|^2=n_T+1.25.
\]

したがって一般の2タスクについて

\[
c_B=\frac{|f_T\cap f_{T'}|+1.25}
{\sqrt{(n_T+1.25)(n_{T'}+1.25)}}.
\]

先生提示式はここまで正しい。

ただし実装は境界ごとに1ビットだけ反転する。反転ビットを除く14ビット中の1の数を q とすれば、0→1 / 1→0 のどちらでも

\[
c_B=\sqrt{\frac{q+1.25}{q+2.25}},\qquad q\in\{0,\dots,14\}.
\]

よって可能範囲は

\[
0.74536\le c_B\le0.96874.
\]

他14ビットが定常 `Binomial(14,1/2)` なら、構造上の参照期待値は

\[
E[c_B]=\sum_{q=0}^{14}\binom{14}{q}2^{-14}
\sqrt{\frac{q+1.25}{q+2.25}}\approx0.941604.
\]

独立な前後15ビットから出る比の代表値約0.57は、隣接境界の null に使わない。

対象:

```text

```

境界は `diff(flip_state)!=0` の左端 B から機械的に取る。1行を `(seed,B)` とし、次を保存する。


`c_direct` は保存 `flip_state` から組み立てた2本の `mu` を正規化して直接内積、`c_formula` は §1 の閉形式。

## 3. 再分類死率

### 3.1 主転帰 — 既存定義との接続

境界 B の全100ユニットについて

```python
risk_005  = p_hat[B] >= 0.05
death_005 = risk_005 & (p_hat[B+1] < 0.05)
r005      = death_005.sum() / risk_005.sum()
```

を使う。これは `dead2path_0821` の再分類死イベントと同じ閾値定義である。

### 3.2 副次転帰 — strict off

```python
risk_strict  = p_hat[B] > 0
death_strict = risk_strict & (p_hat[B+1] == 0)
r_strict     = death_strict.sum() / risk_strict.sum()
```

を同じ方法で報告するが、主判定の差し替えには使わない。

### 3.3 分母ガード

- 主解析は `n_risk_005>=10` の境界だけ
- 10未満は記述用に残すが Spearman から除外
- seed 内で有効境界が 50 未満、c が3水準未満、または r005 が定数なら、その seed の `rho_s=NaN`
- 有効 seed が 8/10 未満なら `M1=INCONCLUSIVE_GUARD`

ガード値を死亡率や相関を見て変更しない。

## 4. 集約と bootstrap

- 各 seed 内で boundary を等重みに Spearman 相関（tie は average rank）
- 10 seed の `rho_s` を等重み平均
- seed 10本を復元抽出する cluster bootstrap
- `B=10000`
- `bootstrap_seed=20260829`
- `OMP_NUM_THREADS=1`
- 同じ resample index で主 `r005` と副次 `r_strict` を回す
- 95% percentile CI = 2.5 / 97.5 percentile
- 非有限 replicate が1件でもあれば CI を出さず `SANITY_FAIL_NONFINITE`

boundary 990本を独立標本として bootstrap しない。

## 5. Sanity gate

次のいずれかが落ちたら主判定を出さない。

1. 10 seed、各20,901点、各seed 99実境界
2. 全境界で変化した flip bit が厳密に1個
3. `n_new-n_old∈{-1,+1}`
4. 全境界で `|c_formula-c_direct|<=64*eps(float64)`
5. c が §1 の理論範囲内
6. `death_005` のイベント行が `dead2path_0821/events.csv` の `path=reclass` と `(seed,unit,B,B+1)` で完全一致
7. `0<=n_death<=n_risk<=100`、率が [0,1]
8. 元列と bootstrap 推定量に非有限値なし（ガードにより定義されない `rho_s` は別扱い）

## 7. 解釈の上限

`NEGATIVE_ASSOCIATION` が出ても、「回転角を介入すると死が増える」という因果効果ではない。タスク状態、境界時刻、alive 構成が同時に動く観察的関連である。

また c は1-bit flipの結果なので可動域が狭い。`INCONCLUSIVE` は、方向回転が無関係であることではなく、既存10 seed・99境界で解像できなかったことを意味する。

## 8. M2 を本 spec・r-swap に入れない理由

先生提案の

\[
S_i(t)=\frac1{32}\sum_x\max(z_i(x,t),0)
\]

は良い動的量だが、既存 `function_blind_direct_0823_confirm` の保存列は `p_hat,pre_max,x,r,w_norm,b,v,utility` までで、32個の preactivation、W本体、または平均 activation を保存していない。これらの要約から S は一意に復元できない。

さらに [[r差し替え解析spec_0824]] は実行済みであり、結果を見た後に M2 を本文へ追加できない。M2 を行うには、同じ config・seed・commit の決定論的再計装リプレイを別 spec で事前登録し、元走との最終state hash bit一致を要求する。これは「既存ログだけの再解析」ではないため、本 spec では実行しない。
