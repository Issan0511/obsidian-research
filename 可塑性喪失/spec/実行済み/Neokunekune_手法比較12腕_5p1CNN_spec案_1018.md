# Neokunekune の手法比較 12 腕（実ラベル 5+1 CIFAR の CNN）— spec 案 1018

状態: **実行済み（2026-10-19）。Issa が承認し lop_analysis に登録（`specs/spec_neokunekune_methods_cifar5p1_cnn_1018.md`、commit `170beea5`）。結果は [[Neokunekune_手法比較12腕_5p1CNN_結果_1018]]（最上位は ELU α 3.6、NEO − ELU `WORSE_THAN_ELU`）。** 本ノートは承認時の案で、登録版は実装の細部（格子の同点の順序・ReDo の手順・束の組み方）を足したもの。
起草: 2026-10-18 夜、Claude（Opus 5.5）。発端: Codex の 12 腕案（Issa 経由で転送）。
前段: [[Neokunekune_5p1CNN_結果_1018]]（登録 [[Neokunekune_5p1CNN_spec_1018]]）。前段は「損失ゲートの効果」の検証として閉じた。

## 1. 目的と問い

前段の 4 腕は、損失ゲート（NEO）が通常の適応 SNA と課題 1 末固定 SNAfrz1 に対してどうかを問うた。結果は D1 `INCONCLUSIVE`、D2 `INFERIOR_TO_FREEZE` だった。本 spec はそれと判定を分け、**手法としての競争力**を問う。

**問い**: 実ラベル 5+1 CIFAR の CNN で、腕ごとに lr と形を較正したとき、NEO と SNAfrz1 は既存の選択肢に対してどこに着地するか。

- 前段の結果を見たあとで設計した。前段の結果を独立に予言したことにはしない。
- 共通の lr だけで勝っても、調整済み手法への優越とは言わない。較正した範囲の外は未測として扱う。

## 2. 箱

前段と同じ箱を使う（[[Neokunekune_5p1CNN_spec_1018]] §2）。違うのは lr を腕ごとに較正することだけである。課題列・batch 列・初期化・診断の probe は seed だけで決まるので、前段とビットで同じになる。TF32 は前段と同じく matmul・畳み込みとも切る。

## 3. 腕（12）

| 腕       | 中身                                                                  | 形の格子                                                            | 格子の中心の出所                                           |
| ------- | ------------------------------------------------------------------- | --------------------------------------------------------------- | -------------------------------------------------- |
| R       | ReLU                                                                | なし                                                              | —                                                  |
| SNA     | 前段と同じ通常の適応 Snake（c = 0.6）                                           | なし                                                              | 前段                                                 |
| SNAfrz1 | 前段と同じ課題 1 末固定                                                       | なし                                                              | 前段                                                 |
| NEO     | 前段と同じ損失ゲート（Lref の窓・床も同じ）                                            | なし                                                              | 前段                                                 |
| SN06    | 固定 Snake α = 0.6（全 site）                                            | なし                                                              | 前段の c と同じ値                                         |
| SN3     | 固定 Snake α = 3（全 site）                                              | なし                                                              | RC CNN の SN3                                       |
| KKT1    | 従来の kunekune。θ = 2αz が [−2π, π] では Snake、外では傾き 1 の直線。α の規則は SNA と同じ | なし                                                              | `cifar5p1_mlp_0920` の KKT1 を conv へ移す              |
| ELU     | ELU(α)                                                              | α ∈ {1, 3.6}                                                    | Lillo & Cheney v4 表 E2: α 3.6                      |
| LK      | Leaky ReLU(a)                                                       | a ∈ {0.1, 0.4, 0.8}                                             | 同表 E2: a 0.4                                       |
| RSL     | Randomized Smooth-Leaky。訓練中は傾き r ∼ U(l, u) を要素ごとに引き、評価は中点           | (c, p, l, u) ∈ {(0.5, 0.5, 0.673, 2.673), (5, 3, 0.125, 0.333)} | 同表 E2 の 5+1 の値と、原典コードの既定値                          |
| ReDo    | ReLU + ReDo（Sokar 2023、conv はチャネル単位）                                | (τ, 周期) ∈ {(0, 1560), (0.025, 1000), (0.1, 1560)}               | Kumar 2024 表 4・Sokar 表 1・`baselines_cifar5p1_1008` |
| L2I     | ReLU + L2 Init（勾配に 2λ(θ − θ₀) を足す、全 10 テンソル）                        | λ ∈ {1e−3, 1e−2, 1e−1}                                          | Kumar 2024 表 4: λ 1e−2                             |

- RSL の式は `rlcifar_mlp_battle_0918` の実装（Lillo & Cheney のコードの写し）を使う。実装前に原典コードと再照合する。
- ReDo は Dopamine の NeuronRecycler に合わせる。スコアは mean|h| を層の平均で割った値で、conv は batch × 位置の平均を使う。休眠の unit は入力重みを初期分布から引き直して bias を 0 にし、出力重みを 0 にする。該当する重みの Adam の m・v を 0 にし、更新番号は変えない。

## 4. 較正

- 較正 seed は 100、101、102 の 3 本。評価 seed 2000〜2009 とは分ける。同じ CIFAR-100 を使うので、外部検証とは呼ばない。
- lr の格子は全 12 腕で {1e−4, 3e−4, 1e−3}。Lillo & Cheney は {1e−4, 1e−3}、Kumar は手法ごとに 1e−4 か 1e−3 を選んでいる。
- 選ぶ量は、較正 seed での後期窓（t = 21, 23, 25, 27, 29）の online 精度の平均。最大の格子点を採る。同点なら表の格子の先頭（文献の値）を採る。
- 発散した格子点は落とし、その数を記録する。
- 選んだ値が格子の端なら `EDGE` と記録する。結果を見てから格子を広げない。広げるときは追補を登録してから行う。
- 格子点は 60 個（固定形の 7 腕 × lr 3、ELU 2 × 3、LK 3 × 3、RSL 2 × 3、ReDo 3 × 3、L2I 3 × 3）。3 seed で 180 run。

## 5. 本走

- 各腕を較正で選んだ設定で、seed 2000〜2009 × 30 課題回す。12 腕 × 10 seed = 120 run を、R = 40 の束 3 つで回す。
- 束の形がそろっていれば、run の算術は束の組み合わせによらない。これは前段の S-indep を延ばした検査で確かめる。
- 前段の 4 腕が lr 1e−4 を選んだ場合も、本走で計算し直す。前段の `per_task.csv` とビットで一致することを S-nochange として確かめる。
- 課題 29 の fresh 対照を全腕で行う。

## 6. 判定（前段のゲートの効果とは分ける）

主量は前段と同じ A（後期 hard 課題の更新前 online 精度）。

| 族   | 比較                                                                 | 数   |
| --- | ------------------------------------------------------------------ | --- |
| 主   | D_X = A(NEO) − A(X)、X ∈ {SN06, SN3, KKT1, ELU, LK, RSL, ReDo, L2I} | 8   |
| 副   | D′_X = A(SNAfrz1) − A(X)、同じ 8 腕                                    | 8   |

- 区間は seed の percentile bootstrap（20,000 回、NumPy の default_rng(1018)、前段と同じ添字行列の作り方）。族ごとに Bonferroni で両側 1 − 0.05/8、分位点 0.003125 と 0.996875。
- ラベル: 下端 > 0 で `BETTER_THAN_<X>`、上端 < 0 で `WORSE_THAN_<X>`、それ以外は `INCONCLUSIVE`。端が閾値と等しいときは満たさない。
- 副のラベルとして、0.5 ポイント幅の非劣性（下端 > −0.005）を併記する。
- 記述: 12 腕の順位表、train・test 精度、最初の 100 更新、fresh − 継続、早期 − 後期、選ばれた lr と形。
- 全 run の完走が前提。1 run でも欠ければ、その腕を含む比較は `INCOMPLETE` にする。

## 7. 実装と検査

前段のエンジン（`src/neokunekune_cifar5p1_cnn_1018.py`）を宿主として import し、改変しない新しいモジュールで腕を足す。

- lr は run ごとの tensor にして Adam に渡す。
- 新しい活性化は、前段の ReLU と同じく束の中で run ごとに選ぶ。
- RSL の乱数は CUDA graph の外で毎更新バッファに引く。
- ReDo は graph の外で、周期ごとに eager に行う。
- 検査は前段の 16 本に次を足す。
  - S-nochange: 前段の 4 腕を lr 1e−4 で回し、前段とビット一致する。
  - 各活性化の値と微分を独立参照と照合する（float64 で導いた上界）。
  - ReDo の休眠の判定・引き直し・Adam の 0 化を、手で書いた参照と照合する。
  - RSL の訓練時の乱数の範囲と、評価時の中点を確かめる。
  - L2 Init の勾配と、run ごとの lr を確かめる。
  - 各検査に変異（わざと壊した版）を付け、検出されることを確かめる。
