## 0. 一行

文字 GPT の箱 M で、FFN の活性化だけを kunekune 族（KKT1・SNA・SNAfrz1）と GELU に替える。中心化（経路を塞ぐ）は 5+1 CNN で幅の暴走で壊れ、文字 GPT でも学ぶ力を落とした。そこで、応答を保つ設計（kunekune 族）が Transformer でどう効くかを見る。

## 1. 経緯

- 中心化の腕（C3H・B3H・B3HB）は、seed 0〜2 で沈降と死を止めたが、学ぶ力をそろって落とした。中心化した腕にはまばらな検出器が無く、深い層の幅が 5〜7 倍に伸びた（事後解析 2）。
- 5+1 CNN では、EMA 中心化（CH′＋B）が幅の暴走で壊れた。幅の 100〜350 倍は重みではなく、層をまたぐ出力のばらつきの掛け算だった。沈降が、正規化層の無い深い経路の尺度のブレーキになっていた（vault 測定/5p1CNN_中心化×予算_CH′Bの損益_結果_1020 の追記）。
- MLP・CNN では、Snake 族は ReLU に大きく勝った（CNN の 12 腕で約 +30 pt）。

## 2. 腕

土台は本走の C3（LN は γ だけ、線形層の bias なし、Adam lr 1e−3）と同じ作りで、FFN の活性化だけを替える。

| 腕 | FFN の活性化 |
| -- | -- |
| KKT1 | kunekune。θ = 2αz が [−2π, π] の内は Snake の曲がり z + sin²(αz)/α、外は直線（左 z、右 z + 1/α） |
| SNA | 適応 Snake。φ(z) = z + sin²(αz)/α、α_i = clip(c/W_i, 0.005, 3)、W_i = √V_i、c = 0.6（2αW の目標 1.2） |
| SNAfrz1 | SNA。課題 1 の末で α と V を固定する |
| GELU | GELU（erf の正確な形）。実物の LLM の活性化の土台 |

- **α と V**：V_i は前活性のバッチ分散（トークン方向）の EMA（β 0.01）。1 更新の順は、更新前の V から α を決め → forward → backward・Adam → この forward の前活性の分散で V を更新、である。KKT1 の α も SNA と同じ規則。MLP（`layer_chimera_cifar_0921.SnakeFamily`）・CNN（`neokunekune_cifar5p1_cnn_1018`）の実装と同じ式と演算の順にした。
- **V の初期値（MLP 版との違い）**：MLP 版は V = 1（α = 0.6）から始める。依頼「α の初期値は FFN 前活性の初期の幅に合わせる」に従い、初期値の網に課題 1 の probe を流し、前活性の unit ごとの分散で V を較正した。fresh の網も同じ較正から始まる。
- **凍結（SNAfrz1）**：課題 2 の頭で V の更新率を 0 にする。課題 1 の間は SNA とビット単位で同じである。
- **そのほか**：本走と同じ箱 M（α 0.01・N_M 10,000・50 課題・fresh は課題 10・25・50）、seed 0〜9。課題 1・10・25・50 の末の checkpoint に Adam の状態も保存する。white-san で、1 seed の 4 腕を KKT1 → SNA → GELU → SNAfrz1 の順に回す（早い seed から 4 腕の対照がそろう）。

## 3. 測る量

- 本走と同じ量：負の割合、μ/σ、死んだ unit（z > 0 のトークンが無い unit）、オンライン超過損失の序盤・終盤、fresh gap、up のノルム、幅 σ、切替直後 100 更新の Δμ/σ。
- 足す量（layer_stats の列）：
  - 局所応答 φ′ の平均（トークン × unit）、unit ごとの φ′ の平均の 10% 点と中央値
  - φ′ の平均が 0.1 未満の unit の割合（Snake 族の「死」の代わり。z > 0 での死は、Snake 族では応答が残るので意味が違う）
  - 応答する割合（φ′ ≥ 0.5 のトークンの割合）の unit ごとの分布：< 0.05、0.05〜0.3、0.3〜0.7、> 0.7
  - Snake 族だけ：α の中央値、2α√V の中央値（ゲートの鋭さ）、2α × 実測の σ の中央値、α が端に張り付いた割合
  - KKT1 だけ：θ が曲がりの区間 [−2π, π] に入っている前活性の割合

## 4. 判定の案

- **主**：終盤（課題 41〜50）のオンライン超過損失の対応差（各腕 − C3）。族は KKT1・SNA・SNAfrz1 の 3 比較で、Holm で補正する。GELU は記述にとどめる。seed で対応させた両側符号検定（n = 10）と対応差の平均 ± SE、「8/10 以上」の規則（本 spec §5 と同じ形）。
- **副**：課題 50 の fresh gap の符号、φ′ の平均、死んだ unit（z と φ′ の両方の定義）、μ/σ の深さ。
- **比較相手の C3**：別マシンの本走の C3 と seed で対応させる（データ列はビット一致、違うのは GPU の丸め）。seed 0 は white-san の C3（crosscheck_white-san）とも比べる。

## 6. 検査（走る前）

`src/chargpt_cl_1019_kune_checks.py`。変異対照つき。
- S-act：φ′ が自動微分の導関数と一致し、KKT1 は継ぎ目で連続。MLP 版の SnakeFamily と一致する。変異（φ′ を 1 + cos にする）は外れる。
- S-engine-k：1 歩目の勾配と V がグラフと eager で完全一致し、3 歩後のずれは C3 の同じ比較のずれの 4 倍以内。
- S-alpha：V の初期値が初期値の網の probe での分散と一致し、更新がバッチ分散の EMA（β 0.01）と一致する。α = clip(0.6/√V, 0.005, 3)。変異（β 0.1 の EMA）は外れる。
- S-freeze：SNAfrz1 の α は課題 2 で動かず、課題 1 では SNA と同じ。変異対照（SNA）は課題 2 で動く。
- S-repro-k・S-inert-k・S-decomp-k・S-adam：記録のバイト一致、測定が V と重みを動かさない、平均の分解、Adam の状態の保存。
- S-base-unchanged：本走の腕 C3 を、このモジュールを通して回しても結果が同じ。

**検査の結果（commit 66dfa07e）：17 項目すべて通過。** φ′ は自動微分と 2.4e−7 で一致し、MLP 版の SnakeFamily とはビット単位で同じ値だった。1 歩目の勾配と V はグラフと eager で完全一致した。SNAfrz1 は課題 2 で α が動かず、課題 1 では SNA とビット単位で同じだった。本走の腕 C3 は、このモジュールを通しても結果が変わらなかった。

## 7. 費用
