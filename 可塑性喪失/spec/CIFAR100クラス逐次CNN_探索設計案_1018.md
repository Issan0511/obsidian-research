# CIFAR-100クラス逐次CNN：小探索の設計案

状態：**設計案 v1・未実装・未実行** / 2026-10-18。
親：[[幅が伸びる実ラベルCNNはあるか_原典と保存結果_1018]]、[[V13背骨と段落地図_1018]]。

Issaが手元CIFAR-100のクラス逐次切替を候補として支持したことを受け、長いContinual ImageNet走の前に試せる案を具体化した。今回行ったのは既存データ・実装の読取とFableによる設計検討であり、GPU学習・forward・データのダウンロードは行っていない。

## 目的と主張の範囲

実ラベルの小型CNNで、自然な学習による幅・位置・応答の変化と、同じ課題を新品の網より学べなくなる差があるかを探す。成立する条件が見つかれば、応答交換や幅への介入、KKT1・ReDo・L2 Init等の同予算比較につなぐ。

これは**二値分類課題を順次学ぶ可塑性の探索**である。100クラスを累積して同時分類するclass-incremental accuracyや、過去課題の保持を主指標にしない。既存5+1・Continual ImageNetの完全再現ではない。幅の成長もLoPも、開始前から成立したものとして扱わない。

## 最初に固定する設定

| 項目 | 案 |
|---|---|
| データ | CIFAR-100のfine label。既存train各クラス500枚を使用 |
| 課題列 | seedごとに100クラスを1回並べ替え、隣接2クラスずつ非重複50課題 |
| 課題内ラベル | pairの前者を0、後者を1。train・test・fresh・全腕で同じ対応 |
| 1課題の訓練画像 | 2クラス×500枚＝1000枚。easy課題を挟まない |
| 入力 | 32×32 RGB、固定のチャネル標準化。task別に統計を作り直さない |
| CNN | Conv5×5 3→16 pad2 → φ → MaxPool2 → Conv5×5 16→16 pad2 → φ → MaxPool2 → Flatten1024 → FC100 → φ → FC100 → φ → 出力2 |
| 正規化・正則化 | BN/LNなし、weight decayなし。biasあり |
| 活性化 | ReLU、ELU（α=1）の2腕 |
| optimizer | Adam、lr=1e−4。共通の診断起点であり手法ごとの最適値とはしない |
| 課題間の状態 | 全重み・bias・Adam m/v/時刻を継続。headもリセットしない |
| 予算 | batch100、100更新/課題と1000更新/課題 |
| 探索seed | 0・1の2seed。各seedで初期化・クラス順・ラベル対応・batch列を腕間で対応させる |

100クラスの非重複二値課題は50課題まで。長くする場合はクラス再訪を伴う別条件として記録し、非再訪のまま100課題などとは書かない。[CIFAR公式のデータ構成](https://www.cs.toronto.edu/~kriz/cifar.html)

二つの予算のbatch列は、seed×taskごとの独立乱数streamで生成し、短予算が長予算のprefixになるようにする。課題1で長く回したために課題2のbatch列まで別になる、という既存runnerの消費順への依存を避ける。モデル初期化・課題順・batch列・診断抽出は独立streamに分ける。

## 計算量と、この予算を選ぶ理由

- 100更新×50課題＝5000更新/run。
- 1000更新×50課題＝50000更新/run。
- 2活性化×2seed×両予算＝**主訓練22万更新**。
- 後述のfreshを課題10・30・50で実施すると、追加は3×(100＋1000)×2活性化×2seed＝13200更新。
- 合計の学習更新は**233200**。診断forward・データ読込・保存の時間は別。GPUの実時間は未計測なので、分・時間の見積もりは出していない。

1課題1000画像・batch100なので、100/1000更新は画像1枚あたり約10/100回の提示に相当する。既存5+1 hardは2500画像・batch32・780/7800更新で約10/100回の提示だった。従って画像提示量の尺度は接続するが、Adamの更新回数・クラス数・CNN構造が異なり、同じ力学だとは主張しない。

短い条件でも探索に情報はある。一方、50課題・1000更新で成長を見つけられなかった場合、その予算を越えた条件まで否定しない。最初から7800更新×50課題の大きい探索へ増やさない。

## 幅と応答の測定

**固定probe**：trainから各クラス20枚、計2000枚を、全seed・全条件共通の固定抽出規則で選ぶ。画像IDを保存する。その画像は該当クラスの通常の訓練にも含まれる。独立汎化評価ではなく、同一入力上での前活性幾何の測定なので、probe専用のholdoutは必須としない。

probeはラベルを使わず、no-gradかつoptimizer・モデル内部状態を変更せずに評価する。未来の課題の画像がprobeに含まれていても、その画像を先にoptimizerへ渡さない。testは探索条件の選択に使わず、汎化成績を別に報告するために保持する。

課題末に固定probeと現在課題画像で、conv1・conv2・FC1・FC2を別々に測る。

- 各unit/channelの前活性平均m・幅s・相対位置r。層中央値だけでなく分布の四分位も保存する。
- convは画像×位置の幅と、位置ごとの画像間分散、位置平均間分散を分ける。中央1位置だけからconv全体の結論を出さない。
- 平均局所導関数mobと、全診断入力で応答しないunitの割合を別々に記録する。mob=0の中央値を全勾配ゼロと読まない。
- 重みの行ノルムは補助指標。sの代わりに使わない。毎stepの全勾配・更新量・共分散行列の保存は初回探索では省く。

固定probeでは入力集合が変わらないため、網の変化を追える。ただし、その中で既に学習したクラスの割合は増える。補助的に、初めの10課題・最後の10課題に属する画像群など、各群の画像IDを時点間で固定した集計も残す。時点ごとにメンバーが変わる「学習済み/未学習」の群だけから、同一入力上の成長や原因を判断しない。当てはめと蓄積の因果分離が済んだとも書かない。現在課題の測定は実際の学習場面を表す。FCだけで幅が成長した場合は「CNN内FCでの成長」と書き、convでも確認したことにはしない。

## 可塑性と学習時間の評価

各課題の指標は次を区別する。

1. **最初の100更新のonline精度**：短予算・長予算に共通の初動指標。
2. **全予算のonline精度**：既存研究との比較用。長い予算では学習後の高精度区間が多くなる点を明記。
3. **訓練終了時の当てはまり**：適応の遅さと最終的にfitできない状態を分ける。
4. **同課題・同予算のfreshとの差**：課題10・30・50で、初期パラメータ・Adamゼロ状態から同一batch列・同一ラベル対応で学習する。最初100更新と全予算の両方を比較。課題1は継続網自体がfreshなので別runは不要。
5. **test精度**：指定時点のみ独立に記録し、訓練onlineの改善と混同しない。探索の条件選択に使用しない。

短予算と長予算では、後期課題へ到達するまでの学習履歴も異なる。最初100更新を揃えることで測定時間の違いを減らせるが、履歴の違いを消した同一網の比較ではない。fresh差を同じ課題内で取ることが、課題難易度の違いとの区別になる。

将来の次課題介入のため、初期化と課題1・25・49末の状態を保存する案とする。課題49→50なら、非再訪50課題の範囲内で次課題の応答介入を構成できる。課題50末から新規クラスの課題51があるとは仮定しない。

## 探索後に判断すること

2seedは候補探索の記述であり、有意差・一般性の主張に使わない。全条件の軌道を残し、条件選択後の確認は別seedで行う。

- freshも初期網も学べない場合は、その予算・設定での学習不足として扱い、履歴によるLoPと呼ばない。
- 同課題freshとの差と応答低下があり、固定probeの後期幅も増える条件は、幅・応答への介入の有力候補。
- gapと応答低下はあるが幅が増えない場合は、応答介入の候補として残せる。幅経路が検証済みとはしない。
- gapが小さい、seedで方向が違う、幅が非単調などの場合は、この探索では条件を特定できなかったと報告する。「LoPが存在しない」とは判定しない。
- 初期適応だけの急増と、後期（課題26–50）の推移を分ける。2seedの終点の一致だけで単調な持続成長を主張しない。

条件が得られた後、KKT1・ReDo・L2 Init等を同じ予算で比較する。既存780更新の順位を移植しない。手法比較・介入の正式なseed数と判定は、探索結果の大きさ・ばらつきと目的に応じて別途固定する。探索の成功を前提に本走や論文の結論を置かない。

## Fableとの検討

Fableには既存のV13セッションを使い、Claude APIで設計を検討してもらった。最初の提案は7800更新・3seedへ拡大するものだったが、ユーザーの時間負担と画像提示回数の対応を踏まえ、親は100/1000更新・2seedの小探索を維持した。3seedでも通常の有意水準の符号検定はできず、探索段階で形式的な検定を要求しない。また、任意のgap閾値を下回っただけでLoPなしとする判定は採用しなかった。

測定用probeの専用holdout、中央1位置だけのconv主指標、MLPの陰性からCNNのELU短予算を省く提案も採用しなかった。採否と最終の検討記録は保存ログへ残す。


第2往復では、画像提示回数の算術、探索2seed、共用probe、分散分解、batchのprefix対応、短い評価窓、ELU短予算を含む点を確認した。Fableはbatch32への変更も提案したが、初回はbatch100を維持し、陰性の範囲をlr1e−4・1000更新/課題以下と明記する。Adamの幅成長を単純な「更新数×lr」で確定する根拠はなく、この積だけから必要予算を決めない。probeの学習済み割合の変化という指摘は、固定画像群による補助集計として取り込んだ。
