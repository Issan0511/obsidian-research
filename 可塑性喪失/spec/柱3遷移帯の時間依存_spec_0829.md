## 0. 一行

柱3 は「eval_loss は ‖µ‖ 2.33 → 3.04 の間でほぼ 0 から 0.37 へ跳ぶ」を閾値型の根拠にしている。**この測定は 1M step で止まっており、下側の `‖µ‖=2.333` 腕は 1M 時点で既に strict_dead 0.556（半数凍結）だった。** 死は進んでいたのに損失がまだ追いついていなかっただけかもしれない。5M へ延ばして、跳びが残るか消えるかを見る。

## 1. なぜ今これを回すか

| 材料 | 出所 |
|---|---|
| 深さ1・std（‖µ‖=3.041）は 1M で eval_loss 0.3667 → **5M で未フィット率 0.856・生存者 1 個** | [[多層Phase0b結果_0829]] `L1w100` |
| 1M では LoP が出ず 5M で出る、が 3 腕で再現した | 同 |
| `‖µ‖=2.333` 腕は 1M 時点で strict_dead 0.556・eval_loss 0.0080 | [[中心主張v4草案_0829]] 柱3 の表（`673c338`） |
| 第2層の dose 7.1–8.5 は遷移帯（dose 単位 9.33–12.16）の**下**なのに壁が立つ | [[多層Phase1結果_0829]] §4-1 |

最後の行が直接の動機。**遷移帯が「1M での見かけ」なら、第2層の話と矛盾しなくなる。**

### 1b 単位の確認（引用時に必要）

柱3 の表の 2.333 / 3.041 は**生の $\|\boldsymbol\mu\|_2$**。dose は $\|\boldsymbol\mu\|/\sqrt{\operatorname{tr}\Sigma/d}$。condA 入力は $d=20$、$\operatorname{tr}\Sigma\approx1.25$（自由 5 ビット × 0.25）なので $\sqrt{\operatorname{tr}\Sigma/20}=0.25$、すなわち **dose = 4‖µ‖**。実測の第1層 dose 12.13 は ‖µ‖=3.041 の ×3.99 で整合する。**遷移帯は dose 単位で 9.33–12.16。**

## 2. スコープと前提

condA・w100・隠れ1層・T=10⁴・batch=1・素の SGD・lr 0.01。`mu_titration_0823` と**同一設定で `total_steps` だけを変える**。condB・多層・他教師へ外挿しない。

## 3. 設計

### 3.1 腕（3 本・新規走）

| 腕 | `center_alpha` | 実測 bulk `mu_norm`（1M 時点） | dose 換算 |
|---|---|---:|---:|
| `mu2333` | 1e-6 | 2.333 | 9.33 |
| `mu1878` | 3e-6 | 1.878 | 7.51 |
| `mu1521` | 1e-5 | 1.521 | 6.08 |

**上端（‖µ‖=3.041・`center_alpha=0`）は新規に回さない。** [[多層Phase0b結果_0829]] の `L1w100` が同一設定・5M の committed 走なので、**参照点としてそれを使う**（late 未フィット率 seed 中央値 0.807、`n_onset` 10）。

> **格の注意**: `L1w100` は別走であり `mu_titration_0823` とは generator が違う可能性がある。**上端との比較は非ペア**として扱う。腕間（`mu2333` / `mu1878` / `mu1521`）は §3.2 の検査が通ればペア。

`mu1521`（dose 6.08）を入れる理由は、**第2層の dose 7.1–8.5 を挟む**ため。7.51 と 6.08 で挟めば「第2層と同じ用量帯で深さ1 は発症するか」に直接答えられる。

共通: m=20, f=15, target_hidden=100, β=0.7, T=10⁴, batch=1, lr_main=0.01, seed 0–9, **total_steps = 5e6（500 タスク）**, device=cpu。

### 3.2 対応づけ

`center_alpha` は乱数を消費しないので、**3 腕は init・教師・入力列・flip 軌道が bit 一致するはず**。

- **S-pair（必須）**: 3 腕の step 0 で bit 一致を確認。通れば **paired bootstrap** を使う
- 上端（`L1w100`）とは**非ペア**

### 3.3 実装

`src/train.py` の既存 `enc=centered` + `center_alpha` をそのまま使う。**新規実装は不要。** config の `total_steps` と `center_alpha` グリッドだけ。

## 5. 集計（事前登録）

### 5.1 窓

早期窓 = タスク 2–11、**末尾窓 = タスク 451–500**（Phase 1 と同じ。平坦域に収める）。

### 5.2 主 endpoint — `mu2333` は 5M で発症するか

各 seed の末尾窓 未フィット率の窓平均 $U_k$（床 `1e-23` でクリップ）。**発症 = $U_k \ge 0.05$**（Phase 0b / Phase 1 から引き継ぎ、変更しない）。

$n_{\rm onset}$ = 発症 seed 数（0–10）。

| `mu2333` の $n_{\rm onset}$ | verdict |
|---|---|
| ≥ 5 | **`THRESHOLD_IS_TIMESCALE`** — 遷移帯は 1M での見かけだった。**柱3 の「閾値型」を書き直す** |
| 0 | **`THRESHOLD_PERSISTS`** — 用量の閾値は本物。第2層の壁は用量以外で説明する必要がある |
| 1–4 | **`PARTIAL`** — これも結果 |

**併記必須**: 全 10 値の $U_k$、中央値・最小・最大。

### 5.3 副 endpoint — 用量反応の形

4 点（‖µ‖ = 1.521 / 1.878 / 2.333 / 3.041）で seed 中央値の $\log_{10}$ 未フィット率を並べ、**1M 時点の同じ 4 点と重ねる**。

- **登録する量**: 隣接点間の $\log_{10}$ 差の最大値 $J$（「跳び」の大きさ）
- 1M では ‖µ‖ 2.333 → 3.041 の間に跳びが集中していた。**5M で $J$ が小さくなる（= 滑らかになる）か、位置が下側へ移動するか**を見る
- **格**: 4 点のうち上端は非ペア・別走。$J$ は記述統計として報告し、**verdict には使わない**

### 5.4 副次（REPORT_ONLY）

`strict_dead` / `alive` / `eff_rank` / `‖w‖` / 壁深さ $D=-\mathrm{median}_i M_i$ の時系列。とくに **`mu2333` の strict_dead が 1M の 0.556 からどこまで進むか**。

**`mu1521`（dose 6.08）と `mu1878`（dose 7.51）が発症するかは、第2層の dose 7.1–8.5 に直接対応する。** 発症すれば「深さ1 でも同じ用量帯で壁が効く」ことになり、[[多層Phase1結果_0829]] §4-1 の矛盾が解ける。**この対応づけは深さをまたぐので、示唆であって証明ではない。**

### 5.5 CI

paired studentized bootstrap、B=10,000、`rng = np.random.default_rng(20260829)`。**Phase 1 と同じ退化検出**（SE < 1e-15 の resample が 1% 超、または CI 幅が点推定の 100 倍超 → `CI_DEGENERATE`、判定は percentile と符号検定へ）。**Phase 0b / Phase 1 では全行退化したので、percentile が主になる見込み。**
