## W1-4. 併せて登録してほしい事後量 3 件

いずれも同じ `verdict.csv` から計算でき、[[現象3存在確認P2b結果_0901]] の記述の訂正に直結する。**すべて `registered = 0`。**

# W2: `LIN0` 腕（隠れ層なしの線形回帰）

## W2-1. 実装するもの

既存 harness に**活性化ではなく別ネット**を足す。`width5_gate_0901` の腕構成に以下を追加する。

**ネット定義**（原典 `lop/nets/linear.py` の `MyLinear` に対応）:

- $\hat y = a^\top x + c$、$a \in \mathbb R^{d}$、$c \in \mathbb R$。**隠れ層なし・活性化なし**
- $d$ は既存の学習器と同じ入力次元（condA の `m` = 20）
- 初期化: 原典は `nn.init.kaiming_uniform_(fc1.weight, nonlinearity='linear')` ＋ `bias.data.fill_(0.0)`。PyTorch の該当規則は gain=1 の一様分布 $U(-b_a, b_a)$、$b_a = \sqrt{3/d}$。**既存 `envs.kaiming_mlp_params` の出力層と同じ規則**（`bv = math.sqrt(3.0/h)`）なので、$h \to d$ に読み替えて流用できる
- $c$ は 0 初期化
- R 系列でベクトル化する（既存の `VecMLP*` と同じ構造）

**★ 乱数消費に注意。** `train.make_gens` の基底は `SEED_BASE[exp] + width + offset`。**`LIN0` の「幅」をどう渡すかで基底が変わる。** 既存 w5 腕と同じ実現を共有したいので **`hidden = [5]` を渡したまま隠れ層を使わない**か、**`hidden = [0]` を渡して基底 `+0` にする**かを決め、`config_used.yaml` と `summary.md` に明記すること。**起草側の推奨は前者**（`width = 5` を渡し、ネットだけ差し替える）——`R5` / `LR5` / `E5` / `LIN5` と教師・入力実現を共有でき、§W2-3 の対比が同一実現上になる。**ただし初期化ドローの本数が変わると系列がずれる**ので、S0′ で既存 4 腕の bit 一致が壊れていないことを必ず確認する。

## W2-3. 判定（案・§W2-7 で確定）

**主判定 G0′**: P2b spec の G0 を、比較相手だけ `LIN5` → **`LIN0`** に差し替える。窓は**末尾（`task 491–500`）と 1M（`task 91–100`）の両方**を登録する（W1 で 1M 窓の規則が入るため）。

$k'_A$ = 腕 $A$ の `unfit` が同 seed の `LIN0` より大きい seed 数（20 中）、Clopper–Pearson 95%。ラベルは P2b spec と同じ（`ABOVE_LINEAR` / `BELOW_LINEAR` / `NOT_SEPARATED_TIGHT`（CI ⊆ [0.20, 0.80]）/ `INCONCLUSIVE_WIDE`）。

**到達可能性は P2b spec §5 のまま**: `ABOVE` には $k\ge15$、`BELOW` には $k\le5$、`NOT_SEPARATED_TIGHT` は $k \in \{9,10,11\}$ でのみ到達可能。

**帰趨判定 G-base**: 6 個のラベル（3 腕 × 2 窓）が `LIN5` 版と**全部一致**するか。

- 全一致 → **`BASELINE_CONSTRUCTION_IMMATERIAL`**。[[原典条件照合_0901]] §2 の差は判定に効かず、§5 の読み替えが確定する
- 1 個でも変わる → **`BASELINE_CONSTRUCTION_MATERIAL`**。**`width5_gate_b_0901` の G0 は原典比較には使えない**ことになり、結果ノートの帰趨を書き換える

**報告のみ**: `LIN0` と `LIN5` の水準差（末尾窓 $\log_{10}U$ 中央値と対応差）、`LIN0` の完全崩壊カウント、`LIN0_lr03` の同一量。

## W2-4. 実行前 sanity

- **S0′（bit 再現・失敗時は本走禁止）**: `LIN0` を足した実装で `R5` / `LR5` / `E5` / `LIN5` の 30k replay が `width5_gate_b_0901` と `p_hat`・`eval_loss_exact`・`unfit` で bit 一致すること。**§W2-1 の乱数消費の懸念を潰すのがこのチェックの主目的**
- **S-lin0**: `LIN0` の出力が入力の厳密なアフィン関数であること（2 点で線形性を 1e-12 以内で確認）。かつ**隠れ層に相当するテンソルが存在しない**こと
- **S-init**: `LIN0` の初期重みが $U(-\sqrt{3/d}, \sqrt{3/d})$ に整合（分位点で確認）、バイアス 0
- **S-floor**: 未フィット率の床は **1 層系 `1e-16`** を `gate_dose_0830` から継承
- **S-mech-na**: `LIN0` には隠れユニットが無いので、3 軸（$s_i$・$m_i$・$R_c$）は**定義されない**。`mechanism.csv` の当該列は**空にする**（[[現在地]] 穴7 の「恒真な列を埋めない」裁定と同型）

# 引用上の注意（両 W 共通）

- **W1 の 1M 窓は事後登録。** 事前登録は末尾窓のみ
- **`LIN0` が入るまで、[[原典条件照合_0901]] §5 の読み替え（`R5_INCONCLUSIVE_WIDE` は原典と整合）は暫定**

- **完全崩壊カウント（`unfit` ≥ 0.999）を「LoP の発症率」と呼ばない。** 測っているのは縮退点への到達であって、絶対的な機能劣化の定義ではない
- `LIN` 系を「線形ネットワーク」と呼ぶときは実装（`LIN0` = 単層／`LIN5` = leaky $a$=1.0 の隠れ 5）を併記する
