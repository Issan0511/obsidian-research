## 2. 候補 A の定義（[[LoP防止アーキテクチャ_0829]] §3 の改訂版）

層 $\ell$ の入力 $\mathbf a^{(\ell-1)}$ に対し

$$\hat{\mathbf a}\leftarrow(1-\alpha)\hat{\mathbf a}+\alpha\,\mathbf a^{(\ell-1)},\qquad z_i=\mathbf w_i^\top\bigl(\mathbf a^{(\ell-1)}-\hat{\mathbf a}\bigr)+\tau_i$$

$\hat{\mathbf a}$ には勾配を流さない。$\tau_i$ は通常の bias として勾配で学習する（初期値 0）。

- **第1層に入れた場合は `src/train.py` の `enc=centered` と同じ演算**（`x_in = x_raw − running_mean`、EMA 更新は forward の直後）。`center_alpha` も既存と同じ 0.01 を使う
- 前向きで $s_i$ の µ 項が消え、後ろ向きでも勾配が中心化入力 $\mathbf a-\hat{\mathbf a}$ を通るので µ 駆動ドリフト（潮流）も消える
- **乱数を消費しない。** これが §3.2 の対応づけの前提

## 3. 設計

### 3.2 腕は**対応がつく**（Phase 0b との最大の違い）

A は乱数を消費しないので、**同じ深さの腕どうしは init・教師・入力列・flip 軌道が bit 一致**する。`ratchet_centered_0822` が `ratchet_log_0819` と対応がついたのと同じ構造。

- したがって `L2_*` の 4 腕は **seed 単位で対応のある比較**ができ、**paired bootstrap を使う**
- `L1w100_A1` は深さが違うので `L2_*` とはペアにならない。**深さをまたぐ paired 比較は禁止**
- **S-pair（§4）でこの前提を検査する。** 検査が落ちたら paired 統計は使わない

### 3.3 実装

Phase 0b の `VecMLPL` と `src/mlp2_phase0b.py` を拡張する。A は層ごとの `centered` フラグとして持たせ、`running_mean` を層ごとに確保する。**勾配は閉形式のまま**（autograd に切り替えない）。

## 5. 集計（事前登録）

### 5.1 窓【8/29 改訂】

早期窓 = タスク 2–11。**末尾窓 = タスク 451–500（50 タスク）**。

> **改訂理由**: Phase 0b の推移（[[多層Phase0b結果_0829]]）で 3 腕とも **task 400 付近で平坦になっている**（末尾 100 タスクの Spearman 中央値が L1w100 +0.045 / L1wide −0.059 / L2 −0.039）。一方で平坦域の振れが大きく、L2 の seed 中央値は 0.151（300）→ 0.031（350）→ 0.277（400）→ 0.047（490）→ 0.096（500）と隣接ブロックで 5 倍動く。**10 タスク窓では平坦域の分散を拾いきれない**ので、平坦域に完全に収まる 50 タスクへ広げる。

### 5.1b 床は実測して凍結する【8/29 追加・Phase 0b の失敗の直接修正】

Phase 0b は `unfit_floor = 1e-12` を決め打ちにし、**実データを切った**。観測された unfit の最小値は 2.956e-15、1e-12 未満の点が 15000 中 1663 点（11%）あり、残差分散の生値は 7.5e-14〜1.2e-13 と float64 の eval としてまだ意味のある領域だった。これが腕依存の左検閲（0.3% / 10.4% / 22.5%）を作った。

**S6 を「床が精度より上にあること」の確認から「床を精度に合わせて決める」較正へ変える。**

- 手続き: `L2_none` の 200k 短走から 20 個のチェックポイントを取り、各点で 32 パターン厳密 eval を**2 通りの総和順序**で計算し `|Δunfit|` を出す
- `floor := 10 × (|Δunfit| の 99 パーセンタイル)` を上に丸めて 10 のべき乗にする
- **決めた値を config に書き戻してから本走を回す。** 本走中は変えない
- §5.3 の `CENSORED` 規則は保険として残す

### 5.2 主 endpoint（co-primary の 2 本）

**P1: 未フィット率の水準**

各 seed で末尾窓の未フィット率の窓平均 $U_k^{\rm arm}$。腕 $A$ とベースラインの対応差

$$\Delta_k = \log_{10}U_k^{A} - \log_{10}U_k^{\rm none}$$

を seed ごとに取り、中央値と **paired studentized bootstrap**（B=10,000、`rng = np.random.default_rng(20260830)`）。**改善 = CI が 0 を下に外す。**

**P2: eff_rank の水準**

各 seed で末尾窓の **読み出し直前の層**（`L2_*` では第2層、`L1w100_A1` では第1層）の eff_rank 窓平均。対応差 $\Delta^{\rm er}_k$、同じ paired bootstrap。**改善 = CI が 0 を上に外す。**

**判定（実行前に凍結）**

| P1     | P2   | verdict                                         |
| ------ | ---- | ----------------------------------------------- |
| 改善     | 改善   | `A_EFFECTIVE`                                   |
| 改善なし   | 改善なし | `A_NULL`                                        |
| 片方だけ改善 |      | `INCONCLUSIVE_SPLIT` — **これも結果。** どちらが動いたかを記録する |
|        |      |                                                 |

P1 は結果（LoP そのもの）、P2 は機構（表現の多様性）。**両方が同じ向きを指したときだけ「効いた」と書く。**

### 5.2b 「LoP を防いだ」のか「1 タスクの学習が速くなった」のか【8/29 追加・必須の判別】

センタリングは条件数を良くするので、**LoP を一切防がなくてもタスク内の収束が速くなるだけで P1 は改善しうる**。P1 単独ではこの 2 つを分離できない。**§8-5 で Issa が第一の疑いとして挙げた交絡**なので、判別を事前登録する。

各腕 × ベースラインの対応差を**早期窓と末尾窓の両方**で取る。

$$\Delta^{\rm early}_k,\qquad \Delta^{\rm late}_k\qquad(\text{どちらも }\log_{10}\text{未フィット率の対応差})$$

| 署名 | 読み |
|---|---|
| $\Delta^{\rm early}\approx 0$ かつ $\Delta^{\rm late}<0$ | **LoP を防いだ**（初期は元から良いので差が出ず、後期にだけ差が出る） |
| $\Delta^{\rm early}<0$ かつ $\Delta^{\rm late}<0$ で**同程度の大きさ** | **タスク内学習が速くなっただけ**の可能性。水準シフトであって傾き変化ではない |
| $\Delta^{\rm early}<0$ かつ $\Delta^{\rm late}$ の方が大きい | 両方が効いている |

**補助**: 各 seed で `log10(未フィット率)` のタスク番号に対する Spearman を全区間（タスク 2–500）で取り、腕間で対応差を見る。**LoP の防止は傾きを下げるはず**で、水準シフトだけなら傾きは変わらない。

判定の格: **本節は P1/P2 の verdict を上書きしない。** `A_EFFECTIVE` が出たときに、その内訳を記述するための登録項目。**「LoP を防いだ」と書けるのは本節の署名が第 1 行のときだけ。**

### 5.2c 整列（Σ 経路）の追跡【8/29 追加・REPORT_ONLY】

**§8-5 の第二の疑い**（µ を閾値未満に落としても LoP は改善せず、Σ による整列が別経路で LoP を起こす）に対応する登録項目。A 腕で `A_NULL` が出たときに、整列が進んでいるかを見る。

層別に時系列で記録する（既存 `src/lop_metrics.py` にある列）:

- `wcos_mean`（重み行ベクトルの pair |cos| 平均）
- `eff_rank_W`・`stable_rank_W`・`top1_frac`
- `sign_match_mean`・`sign_clone_frac`

**読み方（事前に固定）**: A 腕でも `wcos_mean` が baseline と同じように上がり `eff_rank_W` が同じように下がるなら、**µ を消しても整列は進んでいる**ことになる。逆に整列も止まるなら、整列は µ 経路の下流だったことになる。

> **格**: すべて REPORT_ONLY。[[論点マップ]] §2（力場は Σ の主軸を |cos| 0.907 で向くが状態は 0.105）と §3（µ=0 で LoP が出る regime 探しは未解決）の続きであり、**本走はこの問いを閉じない**。materials を取るだけ。



### 5.3 床検閲の扱い【Phase 0b の失敗の直接の修正】

`unfit_floor` は §5.1b で実測して凍結した値を使う。各腕について**床にかかった点の割合を verdict.csv に列として持つ**。

- どちらかの腕で **20% を超えたら** その対比を `CENSORED` と立て、$\Delta_k$ の paired 統計を**判定に使わない**
- fallback: 対応差の**符号検定**（H0: median = 0）。床は単調変換なので順序は保たれ、符号検定は検閲に頑健
- **Phase 0b の §5.4 回帰は、この規則があれば `CENSORED` になっていた**（L2 22.5%）

### 5.4 副次

- 層別の `strict_dead` / `alive` / `‖w‖` / `eff_rank_W` / `dose` の時系列（**すべて REPORT_ONLY**。`strict_dead` は verdict に使わない）
- 第2層の dose の減衰（Phase 0b で 12.81 → 8.16）が A@L1 で止まるか。**A@L1 は第1層の死を止めるはずなので、第2層の µ の枯渇も止まると予想される。報告のみ**
- `eff_rank / alive`（候補 B のベースライン取り）

### 5.5 CI の退化検出と fallback

Phase 0b §5.5 をそのまま継承（SE < 1e-15 の resample が 1% 超、または CI 幅が点推定の 100 倍超で `CI_DEGENERATE`。studentized は報告のみ、percentile と符号検定を併記）。

### 5.6 壁座標

$D^{(\ell)} = -\mathrm{median}_i M_i^{(\ell)}$、32 パターン厳密計算、退化ガード `1e-8`、位相揃え（タスク末尾のみ）を継承。

**A を入れた層では µ 項が定義上ゼロになるので、$M$ も $D$ も verdict に使わない**（S-taut）。介入していない層の $D$ は REPORT_ONLY として意味がある。

## 8. 事前予測（**全項目 記入済み・2026-08-29・実行前**）

1. **`L2_A1`（第1層のみ）= `A_EFFECTIVE`**（Issa）
2. **`L2_A2`（第2層のみ）= `A_NULL`**（Issa）
   - Phase 0b の材料（第2層の壁トレンドが符号検定を通らず p = 0.754、dose も 12.81 → 8.16 に減衰）を見た上での判断
   - **含意**: 第2層の死は自層の µ 壁ではなく、**前層の崩壊による入力劣化**で起きている、という主張になる。支持されれば [[中心主張v4草案_0829]] µ 考察 §3 の「多層ほど regime に入る」の書き直しが確定する
3. **`L2_Aall` は `L2_A1` より良い**（Issa）
   - 2 と併せると「第2層単独では効かないが、第1層を直した上で足すと効く」を予測することになる。**A2 の効果が A1 の有無に依存する（交互作用がある）**という主張で、腕3 と腕1 の対応差がその検定になる
4. **`L1w100_A1` = `A_EFFECTIVE`**（5M でも持つ）（Issa）
5. **外れたときに疑うもの**（Issa・順序は Issa 指定）
   - (i) **「LoP 防止」と「単一タスクの性能向上」は違う。** センタリングは条件数を良くするので、LoP を一切防がなくてもタスク内収束が速くなるだけで P1 が改善しうる。**判別は §5.2b に事前登録した**（早期窓の対応差がほぼ 0 で末尾窓にだけ差が出るのが LoP 防止の署名。両窓が同程度に動くなら水準シフト）
   - (ii) **µ を閾値未満に落としても LoP は改善せず、Σ 等による整列が別経路で LoP を起こす。** [[論点マップ]] §2（力場は Σ の主軸へ |cos| 0.907、状態は 0.105）と §3（µ=0 で LoP が出る regime 探しは未解決）の続き。**追跡は §5.2c に登録した**（A 腕でも `wcos_mean` が上がり `eff_rank_W` が下がるなら、整列は µ 経路の下流ではない）
   - (iii) 上の 2 つが空振りなら **b（τ）経路の罠**を疑う。A は µ 項を消すが b 項は残る（[[論点マップ]] §3「b 経路は整流ではなく片符号ドリフト＋罠」）。作業5 の最低用量 arm（bias share 0.883・strict_dead 0.245）が実測の裏付け
