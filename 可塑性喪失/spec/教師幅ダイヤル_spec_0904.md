## 3. スコープと前提

`gate_dial_0902` §3 を継承するが、**教師幅を変えるので次の 2 つが継承できない**。

1. **committed 対照は使えない。** `R_1216` / `LR_1216` は $H_T$=100 の走なので、$H_T\ne100$ の腕の対照にならない。**`R` と `LR` を本走の中で回す**（$H_T$=100 の 2 腕は committed 走の再現確認にも使う → S-repro）
2. **親走との S-pair は取れない。** `target_hidden` を変えると教師の構成が変わり乱数系列がずれる。**腕どうしの S-pair（同一 $H_T$ 内で init・入力列・flip が bit 一致）だけを取る。** $H_T$ をまたぐ腕は対応しない —— これは**登録された限界**であり、$H_T$ 間の比較は「別の教師での別の走」として読む

床 $10^{-16}$・窓（early 2–11 / 1M 91–100 / 末尾 491–500）・発症 $U_k\ge0.05$・CI（paired percentile bootstrap B=10000・$\Delta$=0.15 dex）は `gate_dial_0902` §5 を逐語継承。bootstrap seed **`20260916`**（`configs/` の既用 20 値 20260819–20260915 に無いことを照合してから確定する）。GPU 不使用。

### 4.3 対応づけ

同一 $H_T$ の腕どうしは init・教師・入力列・flip が bit 一致する（活性化の選択は乱数を消費しない）。**$H_T$ が違う腕は対応しない。** paired 対比は**同一 $H_T$ の中でだけ**取る。$H_T$ 間は unpaired の水準比較として読み、CI は付けない（§8）。

### 4.4 `SN` の dial —— **9/4 に前提が変わった**

> **★ 起草後に判明**（[[櫛の分離結果_0903]] §8-4・§8-5・**未登録診断**）。$\varphi'=1+\sin(2\alpha z)$ の値域は $[0,2]$ で $\alpha$ に依らないが、足す項の振幅が $1/\alpha$ なので前向き比 $E[\varphi^2]/E[z^2]$ は **$\alpha$=1 が山の頂上**（1.352）で、0.1／0.3／3／10／30 は 1.00–1.23。100k step で非有限になるのは **$\alpha$=1 だけ**（1/10）。**登録した $\alpha$=1 は安定性の梯子の最悪点だった。**
> さらに **$\alpha$=3・lr は登録値 0.01 のまま**で 5M を 10 seed 完走し、発症 0/10・横断 1/10・`frozen_abs` 0.0・**`EXACT_FIT` を立てない**（1M 窓 5.2e−4）。
> **したがって下の lr 議論は不要になった。** 本 spec は `SN` を **$\alpha$=3・lr 0.01 の第一級の腕**として置く（dial を振るのは `LR_a0p01` 対 `LR_1216` と同じ格の操作で、ハーネスは他腕と同一のまま）。**§9 #2 の裁定は「lr をどうするか」から「$\alpha$=3 でよいか・$\alpha$=1 も残すか」に変わる。**
> 以下は起草時の議論として残す（[[運用ルール]] §2）。

### 4.4-旧 `SN` の lr —— **裁定が要る**（9/4 に §4.4 で置き換え）

`SN` は $H_T$=100・lr 0.01 で発散した（`comb_isolate_0903`・seed 3・step 1,000）。lr 0.005 なら 5M 完走する（`snake_lr_diag_0903`）。本 spec は **lr 0.01 で統一する**（軸を教師幅 1 本に保つため）ので、

* `SN_w`（lr 0.01）は**発散を許容する腕**。発散したら登録どおり落とす
* `SN_w_lr005`（lr 0.005）は **REPORT_ONLY**。**水準を他腕と比べない**（lr が違う）。読むのは発症数・横断・凍結率だけ

**代案（Issa 裁定・§9 #2）**: 全腕を lr 0.005 に揃える。committed 対照はどのみち使えないので統一のコストは小さいが、**既存の全走が lr 0.01 である**ことと、教師幅と lr の 2 軸が同時に動くことが代償。

### 4.5 実装

**新規実装は最小。** `nets.py` は触らない。`configs/teachw_ladder_0904.yaml` と `src/teachw_ladder_0904.py` を置き、`weird_act_0903._run_arm_weird`（宿主 `gate_dial_0902._run_arm` の写し）と `WeirdRecorder` を import して使う。`condA.target_hidden` を腕ごとに変える必要があるので、**腕表に `target_hidden` を持たせ、`setup_arm_dial` に渡す config を腕ごとに作る**（`_run_arm_weird` は `cfg` を deepcopy するので、腕ごとの `condA` を入れて呼べば足りる —— **実装時に S-teach で検算する**）。

### 4.6 用語

`submerged`・`span`・`frozen`・`frozen_abs`・`EXACT_FIT` は [[櫛の分離_spec_0903]] §4 逐語。`at_well`（$\lvert\bar z_i+\pi\rvert\le0.5$）を `CB1l` / `CB1f` で REPORT。**`SN` は `submerged` を定義しない。**

## 5. 集計（事前登録）

窓・床・発症・CI は `gate_dial_0902` §5 逐語。**判定は W1 → W2 → W3、互いに独立・1 つに畳まない。**

### 5.1 W1 —— 分離幅は存在するか（段 1）

**登録規則**: 各 $H_T$ について
* **対照が生きている** := `R` の early 窓 $U<0.05$ が 9/10 seed 以上（S-cap 通過）
* **逃げ道が消えた** := `CB1l` の 1M 窓 $U$ の seed 中央値 $>10^{-8}$（`EXACT_FIT` が立たない）

$w^\ast$ := **両方を満たす最大の $H_T$**。

| 条件                           | ラベル                                          |
| ---------------------------- | -------------------------------------------- |
| 両方を満たす $H_T$ が 1 つ以上ある       | **`SEPARATING_WIDTH_EXISTS`**（$w^\ast$ を添える） |
| どの $H_T$ でも「対照が生きている」が満たされない | **`CONTROL_BREAKS_FIRST`**（難度を上げると対照が先に壊れる）  |
| どの $H_T$ でも「逃げ道が消えた」が満たされない  | **`ESCAPE_PERSISTS`**（教師幅では厳密補間を塞げない）        |
| 上記以外（両方が別々の $H_T$ でしか満たされない） | **`NO_SEPARATING_WIDTH`**                    |

**★ `NO_SEPARATING_WIDTH` と `CONTROL_BREAKS_FIRST` は失敗ではなく結果である。** 下見（§1.1）はこの側を示唆している。出たら段 2 は回さず、交絡は別の軸（学習器幅・支持点数・順逆分離）へ送る。

### 5.2 W2 —— 戻り道の結論は難度を上げても保つか（段 2・$w^\ast$ で）

段 A（$H_T$=100）で出たのは「`CB1f` 10/10 対 `CB1l` 0/10」。同じことが $w^\ast$ で出るか。

| 条件（すべて $w^\ast$ での値）                       | ラベル                                               |
| ------------------------------------------ | ------------------------------------------------- |
| `CB1f` $n_{\rm onset}$(5M) ≥5 かつ `CB1l` ≤2 | **`RETURN_PATH_HOLDS`**                           |
| `CB1f` ≤2 かつ `CB1l` ≤2                     | **`BOTH_SURVIVE_WHEN_HARD`**（葉が難度で効き始めた）          |
| `CB1f` ≥5 かつ `CB1l` ≥5                     | **`RETURN_PATH_FAILS_WHEN_HARD`**（段 A の結論が難度で倒れる） |
| 上記以外                                       | `PARTIAL`                                         |

添え: paired（`CB1l` − `CB1f`・同一 $H_T$・5M）の CI と符号検定、`at_well` 率、深さ十分位。

### 5.3 W3 —— 難度と LoP の関係（段 1・**梯子・ラベルを作らない REPORT**）

`R` / `LR` / `CB1l` の $n_{\rm onset}$(5M) と median $\log_{10}U$ を $H_T$ について並べる。**paired 対比は同一 $H_T$ の中でだけ取る。** $H_T$ 間は unpaired の水準として並べるだけで CI を付けない。

**登録する量的照合**: `R` − `LR` の paired 差が $H_T$ について**単調に開くか縮むか**。開くなら「難度は LoP を増幅する」、縮むなら「難度は ReLU と leaky の差を潰す」。**どちらもラベルにしない**（$H_T$ 間が unpaired なので）。

### 5.4 副次（REPORT_ONLY）

`SN_w`（lr 0.01）の発散有無と最初の発散 step ／ `SN_w_lr005` の発症・横断・凍結率（**水準は引かない**）／ `EXACT_FIT` が立った腕の一覧（全 $H_T$）／ 全ユニット span と $\lvert v\rvert$ ／ `frozen_abs` ／ 深さ十分位 ／ $k^\ast$ と横断窓の割合（[[謎関数ダイヤル結果_0903]] §9 の様式）。

### 5.5 数値発散

`gate_dose_0830` §5.6 逐語継承。**`SN_w` は発散を許容する腕。** `CB1l` や `R` が発散したらその $H_T$ の行を空にし、W1 の判定からその幅を落とす（落とした幅を `summary.md` に書く）。
