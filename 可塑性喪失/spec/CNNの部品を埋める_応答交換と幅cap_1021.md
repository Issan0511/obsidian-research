## 1. 中心化で保たれたc1応答の双方向交換

run id: `cnn_response_center_1021`

RL-CIFAR leaky 0.1の通常入力LRと中心化入力LRcを、同じseed・課題30末で比べる。同じ年齢・課題履歴の状態を使うため、早期網と後期網の交換より直接に「予防腕が保った応答」の寄与を問える。両腕とも完全保存状態が残っている。

受け手の初期特徴・pool出力・予測を保ち、**c1の活性化の微分場**を他方から与える。それぞれの受け手に同じ演算を通る自己場対照を置き、同じ課題31・同じbatch列で測る。自然網との丸め差は実行前の再現検査で別記する。受け手の入力変換とAdam状態は保持する。LRcの改善がCHBと同じ介入であるとは呼ばず、入力中心化という予防に対する接続として書く。

MaxPoolでは、受け手が選ぶ位置の傾きが実際の逆伝播へ入る。したがって全空間の平均応答だけでなく、その選択位置の応答も測る。平均傾きと傾きの配置を分ける対照の採否・登録判定は、この走の正式specを正とする。

両方向で学習が動けば、「中心化で保たれたc1応答場には、その後の再学習を変える因果効果がある」と言える。中心化の全利益が応答だけで媒介された、CNN全体が線形化した、rank低下が全てを説明した、とはしない。陰性でも、この層・この時点の場だけでは足りないという判定であり、全CNN・全層の応答機構の否定ではない。

## 2. 実ラベルCNNの幅cap

run id: `cnn_width_cap_1021`

幅が増えることを確認済みの5+1 CNN・7800更新/課題を使い、ReLUとELUをそれぞれ自然継続とcapで比較する。元走の両腕・全4層で、課題1末→30末の固定probe幅中央値は10/10 seedで増大した（[[CNN幅capの出発点は幅が伸びる箱か_保存結果監査_1021]]）。これはcapのbatch幅EMAとは異なる測度なので、新natural自身のEMAと固定probe幅も報告する。課題1末から課題30までの予防試験とする。後期checkpointへ突然capを掛ける回復試験とは分ける。

4つの活性化部位の前活性幅EMAを、課題1の無介入再生で測った課題末のbatch幅EMAを基準に抑える。重みとbiasを同率で縮め、局所入力を固定した射影時には相対位置を保つ。入力共分散が変わるCNNで、重みの行ノルムを前活性幅そのものと呼ばない。上流から順に射影し、実際の幅、上限の超過、biasを含む相対位置の変化を記録する。EMAの制御と、全入力上の厳密な幅上限も区別する。

ReLUでは強い学習劣化の救済を、ELUでは応答と再学習速度の変化を問う。**ELU7800は元から新品を上回るので、ELUの比較を「崩壊からの救済」とはしない。** TransformerではReLU capが救ったため、CNNでも「ReLUには効かない」と結果を先取りしない。

## この2本で広がる主張

成功時には、MLPで示した位置経路・応答・幅の介入を、CNNでも対応する操作で検証したと言える。各箱で効果の方向が違えば、それを適用範囲として説明する。全構造で同じ層・同じ順序・同じ効果量になることは要件にしない。

幅成長H5の導出、c1とf2をまたぐ全成績差の媒介分解、CNNの全期間のself/other帳簿は、この2本だけでは埋まらない。これらを今回の実行へ自動追加しない。
